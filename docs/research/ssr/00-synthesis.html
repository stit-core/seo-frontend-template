1Решения

  1. Фреймворк — Astro 7.3 + @astrojs/node (output: 'static' с адаптером standalone, Vite 8.3). Матрица с весами brief-v2 (§2): Astro 437,5 из 500, Nuxt 355, Next 347,5, SvelteKit 322,5, Eleventy 305. Единственный кандидат, у которого ноль JS на контентной странице — дефолт (гидрация на компонент, а не на маршрут), контент лежит внутри FSD-слайса, src/pages совпадает со слоем без ремапов и автоимпортов, а Node-процесс сам отдаёт prerender с TTFB 0,85 мс. Поле HTTP Archive 2026-08: 71 % origin'ов на Astro с хорошим CWV на мобильном против 50,6 % SvelteKit, 38,3 % Next App Router, 28,6 % Nuxt. Запасные: Nuxt 4.5 (максимум SEO из коробки, Vue-проекты) и Next 16.3 (письменный LTS, ISR с общим кешем, тяжёлый React-кабинет); SvelteKit — не запасной. Условия пересмотра — §5.3.
  2. Подтверждено четырьмя spike'ами по единой таблице (§3): JS на контентной странице — Astro 0 / 0 / 0 КБ по умолчанию, SvelteKit 0 только с csr = false на layout (пол гидрации 42 КБ), Nuxt 134–146 КБ (0 лишь с noScripts, без клиентской навигации), Next 138–143 КБ (+17 КБ RSC-префетчей на просмотр); TTFB prerender 0,85 мс (Astro) / 0,86 (SvelteKit) / 1,9 (Nuxt) / 3,5 (Next); образы 316 / 173 / 212 / 233 МБ; все четыре сами отдают prerender (провал Nitro у Start не повторился). У всех origin печётся на билде (site, $env при prerender, site-config Nuxt, metadataBase) — решается штамповкой плейсхолдера при старте (Astro 32 файла за 0–10 мс, Next 152 за < 1 мс) либо рендером на запрос. X-Robots-Tag на prerendered — только Traefik (исключение — proxy.ts Next). Честный 404 у Astro/Nuxt/SvelteKit из коробки, у Next — рецепт из пяти правил.
  3. Инструменты гейта (§4): границы FSD держит ESLint 10 + eslint-plugin-boundaries@7 с import/resolver + no-restricted-imports по @/<layer>/*/* (на фикстурах 17 из 17); Steiger — структурные правила (нашёл 6 из 12: fail-open на целях .astro/.svelte/.vue, слеп глубже первого уровня pages, insignificant-slice off); Biome 2.5 с html.experimentalFullSupportEnabled линтит .astro (не форматирует); astro check; Vitest 5 (getViteConfig, Container API); Playwright 1.63; size-limit 14; негативные фикстуры гейта обязательны. Попутно найден дефект SPA-шаблона: boundaries без резолвера — тихий no-op на @/-импортах.
  4. Имя и роль. Репозиторий шаблона — ssr-frontend-template (имя стоит в публичном roadmap; в прозе роль — «шаблон индексируемого сайта: static-first, SSR по необходимости»). Форк потребителя — <org>/site, сервис в инфре SVC=site → SITE_TAG → compose/site.yml на корневом ${DOMAIN} (перебивает always-on landing); проект может иметь одновременно <org>/frontend (SPA на app.${DOMAIN}) и <org>/site. landing-template из roadmap — пресет этого шаблона (preset: landing | content-site | docs в service.md), не отдельный репозиторий: рантайм, гейт, FSD, Dockerfile, STOP-контракт одинаковы; различаются reference-набор, бюджеты, обязательные kinds.
  5. Отдельный репозиторий, родство с SPA — контрактом обвязки, не общим кодом: docs/reference/kinship.md (identical / near-identical / divergent) + advisory pnpm kin:diff. Общая npm-библиотека — нет. Идентичное ядро: правила forward-only/comments, /plan, settings.json, commitlint, .nvmrc/.npmrc, shared/lib/{cn,invariant}, токен-слой app/styles/index.css (чистый Tailwind v4 CSS — переезжает к любому финалисту).
  6. Архитектура контент-first (framework-neutral): контент по умолчанию в git (Markdown + Zod-коллекции), шов ContentSource (fs | http) для CMS/API; Markdown компилируется на билде, на запрос собирается только страница; четыре режима рендера static | cached | dynamic | client; абсолютные URL — только в <head>, JSON-LD, фидах, sitemap; в теле — корневые относительные; редиректы — данные (content/redirects.yaml, 301/410 сервером, meta refresh запрещён); i18n — параллельные каталоги + translationKey, непереведённое — 404, hreflang только для существующих переводов.
  7. Развилка «prerender ⊥ runtime SITE_URL» (один образ на все среды против абсолютных URL, запечённых на билде): для Astro дефолт — **C: prerender + плейсхолдер https://__site_origin__
    • штамповка в entrypoint** (32 файла за 0–10 мс, один e2e-тест «в ответе нет плейсхолдера», HTML не предсжимать); D: рендер на запрос + memoryCache + routeRules — опция для контента из CMS/API (инвалидация cache.invalidate({ tags }); обязательны single-flight и прогрев — memoryCache не дедуплицирует промахи: 200 параллельных → 141 рендер; /_image на запрос 300–420 мс и RSS до 360 МБ без routeRules); A: build-arg — только одна среда, явной строкой в rendering.md. robots.txt/sitemap.xml/rss.xml/OG/healthz — всегда on-demand.
  8. РФ-специфика (поток 14a, замеры 2026-09-16 с RU-машины): шрифт по умолчанию — Wix Madefor Text (настоящий курсив, кириллица 13,8 КБ) + Onest, Astro Fonts API с subsets: ['cyrillic','latin']; юридический минимум — 152-ФЗ (политика ПДн на сайте, согласие чекбоксом, уведомление РКН, хранение в РФ; трансграничная передача ужесточена 265-ФЗ от 26.07.2026), прямой нормы о cookie-баннере нет; доставка заявки — FORM_DELIVERY из ≥ 2 каналов + durable-спул на диске (Telegram ограничивается РКН с 10.02.2026, бесплатный SMTP Яндекса/Mail.ru закрыт с июня 2026); капча по умолчанию none, при необходимости SmartCaptcha (35,6 КБ), reCAPTCHA (357 КБ) — никогда; Метрика (95,8 КБ) только после согласия, отдельная строка бюджета третьих сторон ≤ 120 КБ; домены GA4/GTM с RU-машины не открываются. Ландшафт CMS: Directus 12 ушёл на MSCL (Core 3 места / 25 коллекций, ключ ежегодно) — исключён; «редактор без git» — Decap CMS поверх Gitea (PKCE, 0 контейнеров); headless — Payload 3.89 (MIT) или свой Go-бэкенд; SaaS-CMS отклонён для РФ.
  9. SEO-канон (MUST-ядро, полностью — 02-seo-canon.md): всё индексируемое — в первом HTML (Google рендерит JS второй волной, dynamic rendering deprecated; Яндекс держит JS-рендеринг в бете и просит выключать его при SSR); честные 404/410/308; один канонический хост, trailingSlash: never; абсолютный self-canonical из SITE_URL; robots.txt/sitemap.xml из runtime config; staging закрыт тремя контурами; i18n через префикс пути без авторедиректов, полный взаимный hreflang + x-default; JSON-LD Organization+WebSite на корне, BreadcrumbList, Article/Product по типу, без FAQPage/HowTo/SearchAction; документ ≤ 2 МБ (лимит Googlebot; бюджет шаблона ≤ 100 КБ, потолок 300 КБ); Яндекс ≠ Google (разрешающая директива побеждает, Host/Crawl-delay мертвы, Clean-param жив, cross-domain canonical не поддерживается).
  10. Рантайм и деплой (полностью — 04-runtime-deploy.md): один Node-образ node:24-alpine, только выход сборки, non-root, HEALTHCHECK /healthz; compose/site.yml с двумя роутерами (apex + www → 301), Traefik compress (encodings: [br, zstd, gzip], без defaultEncoding: zstd), Traefik-side healthcheck + --wait в make bump; кеш без CDN = кеш HTML в процессе + no-cache+ETag на HTML + immutable на хешированных ассетах; keep-alive Node > idle-таймаута Traefik; CrowdSec crowdsecurity/rdns + seo-bots-whitelist, троттлинг ботов только 429. 5.2 Почему не Nuxt (и когда всё-таки Nuxt)

Nuxt 4.5 в spike показал себя самым полным по SEO-инструментарию (26 из 38 MUST из коробки, useLocaleHead, robots в три контура одной env, schema-org, og-image) и самым готовым по рантайму (Nitro 2.13.4 stable, swr со встроенным single-flight, graceful shutdown, образ 212 МБ, 39 МиБ в контейнере). Против него — четыре вещи, каждая из которых для шаблона весит больше, чем удобство модулей:

  1. Нет partial hydration. Контентная страница либо тянет 134–150 КБ JS, либо noScripts выключает гидрацию и клиентскую навигацию на весь маршрут; .server.vue делает хуже (−3 КБ JS, +18 КБ JSON). Профиль «интерактив точечный» этим не описывается.
  2. FSD против течения фреймворка. srcDir/dir.* ремап, обязательные imports.autoImport: false + components.dirs: [] (иначе архитектурный гейт слеп), любой .vue в pages — маршрут (колокации нет), навязанный src/components/OgImage/, mountSuspended несовместим с отключёнными автоимпортами.
  3. Стыки модулей. Три самых дорогих бага spike'а (image.dir от srcDir, i18n.baseUrl молча перебивает runtime site-config, og-image тянет playwright-core) — все на стыках и не диагностируются по сообщению; ipx в проде — beta; доки nitro.build — про другой Nitro.
  4. Nuxt 5 «Scheduled» ~Q4 2026 с переездом на Nitro 3 / h3 v2 — запланированная миграция серверного слоя шаблона в первый же год жизни.

Nuxt — первый запасной вариант: если владелец решит, что «максимум SEO из коробки и минимум собственного кода» важнее «нуля JS по умолчанию», — или если проект-потребитель живёт на Vue. Тогда дефолт — swr + noScripts на весь индексируемый контур, две env-переменные origin, sqliteConnector: 'native', image.dir: '../public', OG-шаблон свой.

6.2 Режимы рендера и развилка абсолютных URL

режим что значит страницы Cache-Control индексируется
static HTML вычислен заранее и живёт до релиза лендинг, /about, юридическое, посты no-cache + ETag да
cached рендер на запрос + кеш процесса (TTL + SWR) списки, теги, каталог из API, главная no-cache + ETag да
dynamic на каждый запрос, кеш запрещён /now, поиск, preview, персональное private, no-store обычно нет
client каркас + данные на клиенте кабинет, приватные калькуляторы private, no-store никогда

Инварианты: indexable: yes ⇒ режим ∈ {static,cached,dynamic} и весь контент в первом HTML; guard ≠ public ⇒ client/dynamic + noindex + private, no-store + нет в sitemap; client + indexable: yes — запрещено (гейт /scaffold).

Развилка «prerender ⊥ runtime SITE_URL». У всех фреймворков канонический хост — build-time (site Astro, $env/dynamic при prerender SvelteKit «bakes in build time values», Nuxt site config подменяется только для SSR-ответов, metadataBase Next). Решение: абсолютные URL нужны только в <head>, JSON-LD, фидах и sitemap — в теле ссылки корневые относительные (проверяется регуляркой в e2e); для финалиста (§5.1, §10 п. 4) дефолт — C (prerender + плейсхолдер https://__site_origin__, штамповка при старте контейнера: 32 файла за 0–10 мс по spike 08; HTML тогда не предсжимать, e2e-тест на остаток плейсхолдера), D (рендер на запрос + кеш в процессе, SITE_URL из env на каждом рендере, single-flight + прогрев горячих URL, X-Cache: HIT|STALE|MISS|BYPASS) — для контента из CMS/API и страниц, которым prerender не подходит, A (build-arg) — одна среда, явная строка в rendering.md. Инвалидация — четыре механизма: релиз · TTL+SWR · вебхук POST /internal/revalidate (HMAC, 202) · ручной POST /internal/cache/flush; ключ кеша — метод+путь+локаль, без cookie/UA/неизвестных query.
