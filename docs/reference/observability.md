# Observability

Сайт отдаёт статику, поэтому наблюдаемость у него маленькая и вся серверная: одна
JSON-строка на on-demand запрос, `X-Request-Id` для сшивки, `/healthz` для оркестратора
и Sentry — только если задан DSN. Клиентского RUM нет: он стоил бы скрипта на каждой
странице.

## Лог процесса

Единственный вывод — `log()` из `src/shared/observability`; `console.*` мимо него не
пишут ни middleware, ни маршруты (ESLint `no-console` в `src`). Одна строка JSON на событие:

```json
{"ts":"2026-01-15T10:03:41.118Z","lvl":"info","method":"GET","path":"/now","status":200,"dur_ms":3,"rid":"..."}
```

| поле | что |
|---|---|
| `lvl` | `debug` \| `info` \| `warn` \| `error`; порог — `LOG_LEVEL` (дефолт `info`) |
| `path` | путь без query |
| `rid` | тот же `X-Request-Id`, что ушёл в ответе и в Sentry |

Уровни: успешный `/healthz` — `debug` (иначе оркестратор зальёт лог), 404 и 410 — `warn`,
исключение рендера — `error` со статусом 500 и тем же `rid`.

**Чего в логе нет и не появится**: IP (он в access-log прокси), cookie, query-строка,
тело запроса и тело заявки. Это инвариант правил `env-local` и `forms-antispam`, а не
настройка: журнал с персональными данными — сам по себе объект 152-ФЗ.

### Что попадает в лог, а что нет

Prerendered-страницы, карту сайта, фиды, `public/*` и `/_astro/*` отдаёт статик-хендлер адаптера
**до** приложения — middleware их не видит, и в логе процесса их нет. Видны только on-demand
ответы: 404, `/now`, `/healthz`, `robots.txt`, файл ключа IndexNow,
обработчик формы и удалённые адреса `content/redirects.yaml` (410) — без `User-Agent`: строка лога
его не несёт. Редирект — переезд по таблице или с неканонической формы адреса — отдаёт обёртка
процесса раньше приложения, строки лога у него нет. Отказ `400` на запрос, который до приложения не дошёл, — самого Node (битый запрос) или
обёртки процесса (`TRACE`, userinfo в `Host`; `deployment.md`) — строки не оставляет. Полная
картина трафика — в access-log Traefik.

### Боты в access-log

Страницы боту отдаёт статик-хендлер, поэтому в логе процесса визита нет — он виден только в
журнале доступа Traefik: запись несёт `User-Agent` запроса (`infra-handoff.md § Edge`). Раз в
неделю — отчёт «бот × статус»: кто приходил и что получил. Команда — на VPS, по журналу и копиям
его ротации, без проб `make accept`: `docs/reference/runbook.md § Отчёт «бот × статус»` в
`<org>/infra`.

Читать так: `429` сериями у поискового или user-fetch бота — его держит лимит или бан CrowdSec
(отказ WAF — тоже 429): edge режет того, кто приносит трафик из ответов, — сверить
`cscli decisions list` и allowlist (`infra-handoff.md § Боты`). `403` у бота — отказ WAF не 429
(`infra-handoff.md § Edge`). `5xx` сериями — бот видит сайт недоступным и снижает обход.
User-Agent подделывают: подозрительную строку сверяют по списку сетей вендора (`ip_list_url`,
`rdns_suffix` записи реестра) до того, как делать выводы.

## `X-Request-Id`

Middleware принимает заголовок от прокси или генерирует свой и возвращает его в ответе.
По нему сходятся три источника: строка лога приложения, запись access-log прокси и
событие в Sentry.

## Ошибки

`@sentry/node` грузится динамически и **только при непустом `SENTRY_DSN`** — сайт без
Sentry не платит за него ни временем старта, ни памятью. Инициализация ленивая, на первом
исключении; трассировка и авто-инструментирование выключены (они требуют init до импорта
приложения, то есть правки `docker/server.mjs`).

| ключ | значение |
|---|---|
| `SENTRY_DSN` | пусто — пакет не грузится вовсе |
| `SENTRY_ENVIRONMENT` | `production` по умолчанию |
| `RELEASE` | версия образа, она же в логе |

В Sentry уезжает исключение с тегами `rid` и `path` — без тела запроса и без заявки.
Отказы антиспам-лестницы (403, 400, 413) событиями не становятся: иначе один бот
сжигает квоту.

DSN **public by design**: Sentry режет по origin и лимитирует поток. Self-hosted вариант —
GlitchTip: совместим по API и SDK, поднимается одним compose (postgres + redis); полный
Sentry self-hosted тяжёлый и оправдан только на больших объёмах.

## `/healthz`

Liveness без зависимостей: `200 ok`, `Cache-Control: no-store`, версия наружу не
раскрывается. Его же ждут `HEALTHCHECK` образа и `webServer.url` Playwright. Отдельного
readiness нет: процесс без внешних зависимостей готов, как только слушает порт.

## Скорость

Метрики собираются без кода на странице:

| что | чем |
|---|---|
| TTFB своего сервера | `pnpm ttfb <origin> <path…>` — медиана и p90 из 20 запросов; медиану главной печатает приёмка образа (`pnpm accept:image`) |
| вес страницы | `pnpm size` (бюджеты HTML и CSS); HTTP-набор гейта — HTML каждой страницы < 300 КБ; `seo:check` — ни скрипта вне островов, ни ресурса с чужого origin |
| CWV живых пользователей | поле в Search Console и Яндекс Вебмастере; PageSpeed Insights по ключевым URL |

## Что не собираем

- Клиентский RUM и web-vitals — цена скрипта на каждой странице выше пользы
- Session replay — приватность
- Ошибки сторонних скриптов — на сайте их нет вовсе, пока не задан счётчик
