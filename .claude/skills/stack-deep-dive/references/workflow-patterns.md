# Три режима ведения сеанса

`stack-deep-dive` поверх дефолтов шаблона (Astro 7 `output: 'static'`, контент в git,
`ru` + `en`, один Node-образ со штамповкой `SITE_URL`, 0 JS по умолчанию) решает **проектные**
вариации. Три сценария входа.

## A. Заведение

**Сигнал**: args = `<kind>`, для которого `docs/stack/<kind>.md` ещё нет.

1. Прочитать `docs/stack/README.md` — освежить каталог и гейт.
2. Скопировать форму: `cp docs/stack/_templates/<kind>.md docs/stack/<kind>.md`.
3. Frontmatter (`kind`, `status: draft`) — тривиально из имени файла, без вопросов.
4. Перейти в режим C на свежезаведённом артефакте.

Если недостающих несколько — предложить через `AskUserQuestion`: завести все
обязательные сразу или только выбранный. Условные (`api`, `analytics`) заводятся
ответом на два вопроса первой волны (`SKILL.md § Первая волна решает состав`).

## B. Сырьё

**Сигнал**: args = свободный текст или приложение (описание сайта, список страниц,
готовый `.env`, брендбук, выгрузка старого сайта).

1. Прочитать материал внимательно.
2. Привязать каждое решение к kind'у: имя/registry/домены → `service`; память и
   таймауты → `runtime`; типы контента, кто пишет тексты, картинки → `content`;
   адреса страниц и редиректы → `routing`; что меняется чаще релиза → `rendering`;
   бренд, хост, OG, robots → `seo`; палитра и шрифты → `styling`; форма и внешние
   данные → `api`; счётчики → `analytics`; лог и ошибки → `observability`; env →
   `config`; пакеты и бюджеты → `dependencies`.
3. Показать план в чате, подтвердить волной `AskUserQuestion`.
4. Завести/обновить артефакты как драфты. Дыры по обязательным секциям —
   `**blocker**` в `state/<kind>.md`.

**Что НЕ делать в режиме B**: объявлять извлечённое зафиксированным до подтверждения;
угадывать `Generates`; выдумывать env-имена, хосты и версии.

## C. Углубление

**Сигнал**: args = `<kind>` существующего артефакта, либо выбран из сводки.

1. Прочитать артефакт целиком и `state/<kind>.md`, если есть.
2. Прочитать соседей по cross-kind: правишь `content`/`routing` → проверь
   `rendering`; правишь `seo`/`api`/`analytics`/`observability` → проверь, что их
   env доехали в `config`.
3. Прогнать обязательные секции по `references/field-checklists.md`. Искать: пустые
   секции, курсивные заглушки, **пустой `Generates`**, anti-pattern'ы, cross-kind drift.
4. Раунд `AskUserQuestion` — до 4 вопросов, точечно по дырам.
5. Применить ответы через `Edit`. Зеркальную правку `config` — черновиком, потом подтвердить.
6. Прогнать `references/draft-stable.md`. Всё сходится → промоушн.

## Каскады / cross-kind drift

- `config.md` — роллап env всех kind'ов. Drift помечается `**blocker**` в
  `state/config.md`: «`api` объявил `SMTP_URL` — добавить в таблицу».
- `rendering.md` — роллап маршрутов: страница из `routing.md` без режима — `**blocker**`
  в `state/rendering.md`.
- `content.md § Кто редактирует` — единственная организационная секция набора, и она
  блокирующая: редактор без git при источнике `git` означает, что проект физически не
  сможет вести контент.

## Стиль вопросов

- Не спорить о дефолтах шаблона — они решены; несогласие идёт issue в шаблонный репо.
- Имена сервиса, хостов, env, версий — Other: их называет архитектор, а не скилл.
- Спрашивать смысл, а не механику: «что меняется чаще релиза» вместо «какой TTL».
- Не закрывать сессию без чек-листа хотя бы по одному правленому артефакту.
