# Формат заметки `state/<kind>.md`

Память скилла — рабочее состояние знания о платформенном артефакте.
**Не журнал**.

Лежит рядом со скиллом (`.claude/skills/stack-deep-dive/state/`) и
**коммитится** — общая проектная память между сессиями и архитекторами.
Не часть артефактного канона `docs/stack/` (туда уходят зафиксированные
платформенные решения). Forward-only: только текущее открытое, не
«было/стало», без дат сессий. Это держит `git log` чистым — коммиты в state
маленькие и тематические («закрыл blocker про Sentry self-hosted»), а не нарратив.

Стек — 8 фиксированных singleton-артефактов (`service`, `runtime`, `config`,
`routing`, `api`, `styling`, `observability`, `dependencies`), поэтому путь
плоский: `state/<kind>.md` (без вложений). Контракт зеркалит формат
fsd-deep-dive.

## Шаблон

```markdown
---
kind: observability
ref: docs/stack/observability.md
---

## Открытые вопросы
- Sentry SaaS или self-hosted? от этого зависит DSN в `config.md`. (**blocker**)
- Включаем ли Sentry session replay, или это privacy-риск для проекта?

## Платформенные решения
- `API_BASE_URL` — runtime config (`window.__APP_CONFIG__`), не build-time:
  один образ под все среды.

## Что копать дальше
- После выбора Sentry — добавить `SENTRY_DSN` в `config.md § Runtime config keys`.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 8 stack-kinds | подсказка |
| `ref` | путь к артефакту от корня репо | удобная ссылка в редакторе |

## Секции

Все три опциональны.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — блокирует stable.
- Закрытый вопрос **удаляется** (не зачёркивается). Пусто → удалить секцию.
- Falsifiable формулировка. Хорошо: «Нужен ли Sentry self-hosted, если SaaS
  покрывает объёмы?». Плохо: «разобраться с observability».
- **Cross-kind blocker** (kit-артефакт объявил env, который не появился в
  `config.md`) — частый случай для стека. Помечать в state того роллапа,
  который недополучил: `state/config.md` → «`observability` объявил
  `SENTRY_DSN` — добавить в Runtime config keys (**blocker**)».

### `## Платформенные решения`

Список неочевидных смысловых решений, не влезших в артефакт по форме.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было/стало», без дат.
- Если решение уже растворилось в самом артефакте — удалить отсюда.

### `## Что копать дальше`

Список локальных «следующих шагов».

- Не путать с открытыми вопросами: шаг — задача, вопрос — неясный смысл.
- При выполнении — удалить строку. Пусто → удалить секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать.
- **Перезаписывается** свободно.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Артефакт промоутнут в `stable` без blocker'ов — заметка может остаться
    только если в ней непустые `## Платформенные решения`.

## Что НЕ хранить

- Историю изменений (это `git log`).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого артефакта (env-имена, версии — это в самом файле).
- Подсказки от модели «обычно на проде делают так-то» — это не решение
  архитектора, не пишем.
