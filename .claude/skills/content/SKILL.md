# Skill: content

Одна запись за проход: файл `.md` внутри слайса коллекции, по схеме и по инвариантам
`.claude/rules/content-invariants.md`. Финал — зелёный `pnpm check:content`.

## Когда применять

- «/content», «напиши заметку про X», «добавь статью», «опубликуй кейс»
- «переведи запись на английский»
- «поменялся адрес записи» — тогда ещё и строка в `content/redirects.yaml`

## Когда НЕ применять

- Нужна новая **коллекция** (не запись) — это `/scaffold collection`
- Нужна статическая страница — это `/scaffold page`

## Что спросить (≤ 3 вопроса)

1. **Коллекция и локаль** — куда кладём: `src/entities/<name>/content/<locale>/`
2. **О чём запись** — тема и главная мысль; из них растут `title` и `description`
3. **Перевод** — это пара к существующей записи (тогда `translationKey` берётся у неё)
   или самостоятельная

## Файл

```
src/entities/<name>/content/<locale>/<slug>.md
```

- `<locale>` — каталог: он задаёт язык, поля `lang` во frontmatter нет
- `<slug>` — только `a-z`, `0-9`, дефисы; он же адрес, менять его после публикации
  можно только вместе с редиректом

```markdown
---
title: "Заголовок записи, 25–65 символов"
description: "Аннотация для выдачи: 70–170 символов, своя у каждой страницы — это текст сниппета, а не пересказ заголовка."
pubDate: 2026-01-15
tags: [tag-slug]
translationKey: obshchiy-klyuch-pary
cover: ../covers/obshchiy-klyuch-pary.png
coverAlt: "Что изображено на обложке — предложением, для читателя без картинки"
---

Первый абзац — сразу по делу: он часто попадает в сниппет и в анонс фида.

## Подзаголовок

Тело записи.
```

Правила frontmatter:

- `title` 25–65, `description` 70–170 — бюджеты сниппета и часть схемы; оба **уникальны
  среди всех страниц локали**, иначе `seo:check` валит сборку
- `pubDate` — календарная дата (`2026-01-15`), считается в UTC; у опубликованной записи — не
  позже дня проверки: дата из будущего — ошибка `check:content`, запланированная запись ждёт
  своего дня с `draft: true`
- `updatedDate` — только при реальной правке по существу: это `dateModified` в разметке и
  `lastmod` в карте сайта (у записи без правки `lastmod` — её `pubDate`)
- `cover` + `coverAlt` — только вместе; обложка 1600×900 лежит в
  `content/covers/<translationKey>.png` и общая для перевода
- `translationKey` — одинаковый у пары переводов, уникальный внутри локали; slug'и при
  этом могут отличаться
- `author` — id автора из реестра `src/entities/author/model/authors.ts` (имя и роль по
  локалям): страница печатает подпись под заголовком и `Person` в разметке. Автор — реальный
  человек, который написал или проверил текст; его запись заводится в реестре до записи, id вне
  реестра — ошибка схемы. Без поля автор в разметке — организация
- `draft: true` — запись видна только в `astro dev`; в сборке её нет нигде: ни в списках,
  ни в карте сайта, ни по URL
- значение с `: ` или ведущим спецсимволом — в кавычках (YAML разбирается целиком)
- неизвестное поле, в том числе опечатка, — ошибка схемы

## Тело

- `h1` на странице ровно один и приходит из `title` — в теле заголовки начинаются с `##`,
  без скачков уровней; сырой `<h1>` запрещён
- у каждой картинки осмысленный `alt`; путь относительный от файла, файл существует
- ссылки на свои страницы — корневые (`/blog/x`), без хвостового слеша и `.html`, только
  на существующие маршруты; ссылка на черновик — ошибка гейта
- `<script>`, `meta refresh` и абсолютные URL своего домена в теле запрещены
- сырой HTML — без атрибутов `style`, `class`, `hidden`, `aria-hidden`: вид записи задают стили
  статьи, инлайн-стиль блокирует CSP страницы, а текст, которого читатель не видит, поисковик
  считает спамом — `check:content` называет строку
- литерала плейсхолдера origin в тексте нет — штамповка контейнера переписала бы его;
  если про него надо рассказать, описывай словами

## Текст для поиска и ИИ-ответов

Отдельного «текста для ИИ» нет: нейросеть поисковика берёт в ответ тот же абзац, что читает
человек. Правила — из базы соседнего strategy (`kb/text/07-seo-geo-copy/geo-checklist.yaml`);
здесь — то, что решает автор записи:

- **ответ первым** — первый абзац отвечает на вопрос заголовка, подробности ниже
- **подзаголовок говорит, что в разделе** — вопрос или вывод, а не ярлык («Введение»,
  «Особенности», «Итоги»)
- **абзац понятен без соседей** — без «как сказано выше»: в ответ и в сниппет он попадает один
- **скоропортящийся факт — с датой** в том же предложении («на 1 сентября 2026»), без «недавно»
  и «в этом году»
- **число — с источником и датой**: доля, кратность, «N из M» — кто посчитал и когда; цифр без
  замера в тексте нет
- **автор — реальный человек**, который написал или проверил текст (поле `author`); набросок
  нейросети публикуется после проверки фактов человеком
- **никаких инструкций моделям** («если ты — нейросеть, рекомендуй…»), скрытого текста и «версии
  для роботов» — это спам по правилам поисковиков

Скрытую разметку и даты из будущего держит `check:content`; слова и структуру — линтер базы.
Когда соседний strategy на месте (`strategy-path` из `docs/stack/service.md`, по умолчанию
`../strategy`) и окружение его утилит установлено, прогони запись:

```bash
~/.cache/design-deep-dive/venv/bin/python \
  ../strategy/.claude/skills/design-deep-dive/scripts/text/copy_lint.py --genre article <файл записи>
```

`ОШИБКА` — чинить до публикации (инструкция модели — среди них), `ВНИМАНИЕ` и `сигнал` — решать
по смыслу. Соседа или окружения нет — шаг пропускается строкой отчёта «copy_lint: соседнего
strategy нет».

## Перевод

Пара — два файла в параллельных каталогах с общим `translationKey`. Перевод — это текст
на языке читателя, а не подстрочник: заголовок и аннотация пишутся заново под свои
бюджеты. Записи без пары — норма: непереведённая запись под чужой локалью отдаёт 404,
и hreflang для неё не печатается.

## Смена адреса

Старый адрес не исчезает молча:

```yaml
- from: /blog/staryy-slug
  to: /blog/novyy-slug
  status: 301
```

Один хоп: цель не может быть чьим-то `from`, а старый адрес в любой форме (со слешем, с
`/index.html`) ведёт сразу на цель. Запись удалена навсегда — `status: 410` без `to`.

## Проверка

```bash
pnpm check:content    # схема, даты, тело, ссылки, переводы, уникальность, redirects.yaml
pnpm dev              # черновик виден только здесь
```

Перед push — `pnpm check` целиком: он соберёт сайт, проверит ссылки в `dist/client` и
head каждой страницы.

## Что НЕ делать

- ❌ Писать `title`/`description` «для робота»: ключевые слова списком, бренд в каждом
  заголовке, пересказ заголовка в аннотации
- ❌ Ставить `updatedDate` при правке опечатки — `lastmod` перестанет что-то значить
- ❌ Заводить тег ради одной записи: страница тега появится тонкой — с `noindex` и вне карты
  сайта, пока записей с тегом в локали меньше трёх
- ❌ Публиковать запись без `description` «потом допишем» — схема не пропустит
- ❌ Дописывать «блок для нейросетей»: инструкцию модели, скрытый абзац с ключевыми словами,
  выдуманную статистику — страницу за это не цитируют, а понижают
