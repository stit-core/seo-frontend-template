# harden-runtime — прод и стек: образ не стартует криво, заголовки безопасности, стек не гниёт

## Цель
Вторая фаза программы `audit-program` (P2). Сейчас опечатка в env поднимает полуживой контейнер, `SITE_URL`
подставляется в `sed` без экранирования, staging отдаёт страницы без `X-Robots-Tag`, CSP не ставит никто,
`/_image` кладёт сервер, pnpm прибит к 10.0.0 через corepack, а политики обновлений нет. После фазы образ
отказывает громко и безопасно, заголовки безопасности распределены между приложением и инфрой без дыр, стек
обновляется по правилу, а не по случаю.

  условия; здесь — готовность и правило.

## Решения
- Схема env для `docker/*` — модуль серверной сборки `dist/server/runtime-config.mjs` (`emitFile` в плагине
  `astro.config.ts`), а не вторая реализация в обёртке и не TS-исходник в образе — одна схема и общий с
  приложением экземпляр модуля: проверка при старте и есть тот разбор, что читают запросы.
- Разбор env кешируется по снимку значений ключей схемы — запросы не гоняют Zod, а `vi.stubEnv` и инъекция
  env в тестах остаются верными без сброса кеша.
- `KEEP_ALIVE_TIMEOUT_MS` и `SHUTDOWN_TIMEOUT_MS` — ключи схемы, мусор — отказ старта, а не
  «предупреждение и дефолт» — правило «опечатка в любом ключе — отказ» (AC1); `PORT`/`HOST` читает адаптер, их
  мусор и так роняет старт (`ERR_SOCKET_BAD_PORT`, `listen failed`).
- Ошибка конфига — `invalid env — <ключ>: <правило>` без значения и по-английски, как остальные строки
  процесса (сообщение ключа IndexNow переведено) — среди ключей есть секреты.
- Тест обёртки — раскладка образа во временном каталоге, где модуль конфига переотдаёт TS-исходник схемы
  (Node снимает типы) — проверка идёт в шаге `test` до сборки; связку на настоящей сборке держит HTTP-набор:
  его серверы стартуют через неё.
- Штамповка — Node-скрипт `docker/stamp.mjs`, `entrypoint.sh` — только он и `exec`: правило `SITE_URL` одно
  (поле схемы), а замена строкой (`split`/`join`) данные не исполняет. Правило — регулярное выражение «ровно
  origin», а не `new URL(…).origin`: URL-парсер пропускает в хост `&` и другие символы; IPv6 не принимается.
- Штамповка проверяет env целиком, а не один `SITE_URL` — контейнер с кривым env не трогает файлы; обёртка
  сервера проверяет снова: её запускают и без entrypoint (`pnpm start`).
- Модуль схемы штамповка берёт из `DIST_DIR` (`<dist>/server/runtime-config.mjs`) — правило той сборки, которую
  штампует (копия в HTTP-наборе, временный dist тестов).
- Заголовок staging пишется в `writeHead` ответа, а не одним `setHeader` из демо аудитора: адаптер передаёт
  заголовки маршрута туда же, и `noindex` служебных файлов и 410 перекрыл бы политику процесса — проверка
  staging «каждый on-demand ответ — `noindex, nofollow`» покраснела бы.
- `accept:image` проверяет заголовок staging на странице сборки, а не на `/healthz`, запись блога про staging
  переписана (`updatedDate`) — обе описывали статику staging как закрытую только на Traefik.
- `/_image` закрыт документированным `image.endpoint.entrypoint` (свой обработчик маршрута, который вводит Astro);
  подмена — в хуке `astro:config:setup` только для `command === 'build'`, как адаптер сам выбирает endpoint
  по команде: в `astro dev` картинки страниц идут через `/_image`. Ответ — 404 текстом без рендера страницы:
  поток запросов не стоит процессу ничего, кроме строки лога.
- Edge отвечает на `/_image` 403 (`ipAllowList` на `127.0.0.1/32`), а не 404: у Traefik нет штатного «ответить
  404»; приложение за ним и так отвечает 404. Хвост — `sharp` рантайму не нужен (бэклог `runtime-sharp`).
