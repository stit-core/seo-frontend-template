# harden-runtime — прод и стек: образ не стартует криво, заголовки безопасности, стек не гниёт

## Цель
Вторая фаза программы `audit-program` (P2). Сейчас опечатка в env поднимает полуживой контейнер, `SITE_URL`
подставляется в `sed` без экранирования, staging отдаёт страницы без `X-Robots-Tag`, CSP не ставит никто,
`/_image` кладёт сервер, pnpm прибит к 10.0.0 через corepack, а политики обновлений нет. После фазы образ
отказывает громко и безопасно, заголовки безопасности распределены между приложением и инфрой без дыр, стек
обновляется по правилу, а не по случаю.

## Контекст
- Программа, метод и решения владельца (R16 — пакет правок `docker/*` разрешён; R17 — CSP в приложении,
  `/_image` закрыт на edge; R24 — стек) — `audit-program.md`.
- Находки фазы (подробности, `file:line`, воспроизведения — `~/.cache/stit-ssr-audit/reports/`): `security.md`
  SEC-01…09 (CSP, `/_image` — DoS, ленивая валидация env, инъекция в `sed`, `pnpm audit`, заголовки инфры, лимит
  тела, origin-check, методы и симлинки статики; сценарии — `M/security/`); `seo.md` SEO-02 (`X-Robots-Tag` в
  staging), SEO-08 (Last-Modified на каждом старте); `geo.md` GEO-09 (опечатка env → `robots.txt` 500); `stack.md`
  STK-02…07, STK-10…12 (pnpm и corepack, политика обновлений, конфиг pnpm 11/12, TypeScript 7, патч Astro, peer и
  a11y-плагин, Node 26, дрейф версий, причина запрета `@astrojs/sitemap`); `tests.md` TST-11 (дренаж и `exec` —
  в `accept:image`) и хвост P1 — таймаут шага «старт без `SITE_URL`».
- Гейт после P1: `pnpm check` (покрытие с храповиком, HTTP-набор на копии сборки с настоящими `entrypoint.sh` и
  `server.mjs`, гейт на гейт); `pnpm test:e2e` и `pnpm accept:image <образ>` — шаги `/release`. Правки `docker/*`
  проверяются HTTP-набором и приёмкой образа; Docker — через `M/exclusive.sh`.
- Острова изменит P4 (остров предпочтений, острова движения по бюджету): CSP строится так, чтобы новый остров
  добавлялся одной строкой политики, а не правкой механизма.

## Не входит
- Политика согласия на счётчики и баннер — P5 (R06); здесь CSP учитывает Метрику только как опциональный
  внешний скрипт.
- Allowlist ИИ-ботов в CrowdSec, `compose/site.yml`, сами заголовки Traefik — P7 в infra-шаблоне; здесь —
  контракт в `docs/reference/infra-handoff.md`.
- Смена мажоров (pnpm 11/12, TypeScript 7, Node 26 по умолчанию) — по политике обновлений, когда выполнены её
  условия; здесь — готовность и правило.

## Решения
- Схема env для `docker/*` — модуль серверной сборки `dist/server/runtime-config.mjs` (`emitFile` в плагине
  `astro.config.ts`), а не вторая реализация в обёртке и не TS-исходник в образе — одна схема и общий с
  приложением экземпляр модуля: проверка при старте и есть тот разбор, что читают запросы.
- Разбор env кешируется по снимку значений ключей схемы — запросы не гоняют Zod, а `vi.stubEnv` и инъекция
  env в тестах остаются верными без сброса кеша.
- `KEEP_ALIVE_TIMEOUT_MS` и `SHUTDOWN_TIMEOUT_MS` — ключи схемы: мусор — отказ старта (AC1), а не «дефолт с
  предупреждением»; `PORT`/`HOST` читает адаптер, их мусор и так роняет старт (`ERR_SOCKET_BAD_PORT`).
- Ошибка конфига — `invalid env — <ключ>: <правило>` без значения и по-английски, как остальные строки
  процесса (сообщение ключа IndexNow переведено) — среди ключей есть секреты.
- Тест обёртки — раскладка образа во временном каталоге, модуль конфига переотдаёт TS-исходник схемы (Node снимает
  типы): проверка в шаге `test` до сборки; связку на настоящей сборке держит HTTP-набор — его серверы стартуют так.
- Штамповка — Node-скрипт `docker/stamp.mjs`, `entrypoint.sh` — только он и `exec`: правило `SITE_URL` одно
  (поле схемы), а замена строкой (`split`/`join`) данные не исполняет. Правило — регулярное выражение «ровно
  origin», а не `new URL(…).origin`: URL-парсер пропускает в хост `&` и другие символы; IPv6 не принимается.
- Штамповка проверяет env целиком, а не один `SITE_URL` — контейнер с кривым env не трогает файлы; обёртка
  сервера проверяет снова: её запускают и без entrypoint (`pnpm start`).
- Модуль схемы штамповка берёт из `DIST_DIR` (`<dist>/server/runtime-config.mjs`) — правило той сборки, которую
  штампует (копия в HTTP-наборе, временный dist тестов).
- Заголовок staging пишется в `writeHead` ответа, а не одним `setHeader` из демо аудитора: адаптер передаёт
  заголовки маршрута туда же, и `noindex` служебных файлов и 410 перекрыл бы политику процесса — проверка
  staging «каждый on-demand ответ — `noindex, nofollow`» покраснела бы.
- `accept:image` проверяет заголовок staging на странице сборки, а не на `/healthz`, запись блога про staging
  переписана (`updatedDate`) — обе описывали статику staging как закрытую только на Traefik.
- `/_image` закрыт документированным `image.endpoint.entrypoint` (свой обработчик маршрута, который вводит Astro);
  подмена — в хуке `astro:config:setup` только для `command === 'build'`, как адаптер сам выбирает endpoint
  по команде: в `astro dev` картинки страниц идут через `/_image`. Ответ — 404 текстом без рендера страницы:
  поток запросов не стоит процессу ничего, кроме строки лога.
- Edge отвечает на `/_image` 403 (`ipAllowList` на `127.0.0.1/32`), а не 404: у Traefik нет штатного «ответить
  404»; приложение за ним и так отвечает 404. Хвост — `sharp` рантайму не нужен: бэклог `runtime-sharp` (≈ 20 МБ
  из 359; prod-deps без него — правка вне шагов этапа).
- Выход сборки живёт в образе: штамповка отказывает без `dist/client/index.html` (пустой bind или tmpfs подняли бы
  живой `/healthz` без сайта), том на `/app/dist/client` в контракте запрещён — именованный том после `make bump`
  отдал бы прошлый релиз, поэтому вариант «read-only корень + writable-bind» снят, а не описан.
- Запись штамповки без прав (EROFS, EACCES) — строка `[entrypoint] cannot stamp <файл>: <код>` вместо стека Node;
  тест — файл `0444`, под root он не воспроизводится и пропускается.
- Origin — метки хоста непустые, порт 1–65535 без ведущих нулей: регулярное выражение и число порта, а не
  диапазон цифрами в выражении — так правило читается.
- Полный список «не origin» живёт в юните схемы (в процессе), обёртка и entrypoint получают по три значения —
  их дело применить ту же схему, а entrypoint — не исполнить строки-инъекции; опечатки значений — одним
  запуском обёртки: тест процессов не запускает Node на каждое значение.
- Схема ловит значения вне формата (enum, число, ключ IndexNow, origin). Свободные строки — адрес канала формы,
  DSN — проверяет их потребитель; имя ключа с опечаткой (`ROBOT_POLICY`) для схемы — незаданный ключ. Детектора
  похожих имён нет: эвристика по расстоянию срабатывала бы на чужих ключах окружения, а staging закрывают
  контуры Traefik — тексты сужены до правды.
- Роутер edge на `/_image` — `Path(/_image) || PathPrefix(/_image/)`, а не префикс имени: файлы `public/_images/…`
  и `/_image-*.png` форка до него не доходят; приоритет 1000 — выше длины правила `site` при любом домене (умолчание
  Traefik — длина правила, с доменом от 56 символов `/_image` ушёл бы в приложение).
- Хеш острова закреплён строкой `ISLANDS` (`hash`), а не вычисляется из исходника на сборке: правка
  исполняемого кода сайта — правка политики в диффе, как SRI. Держат три слоя: тест острова (тело = хеш политики,
  у счётчика — без сборки), HTTP-набор (CSP у каждой страницы против её инлайн-скриптов и стилей) и браузер.
- Новый остров — строка `ISLANDS`: имя и хеш тела (печатает упавший тест острова), `on` — если остров печатается
  не всегда, `sources` — его чужие origin по директивам CSP. Механизм CSP при этом не правится.
- Директива CSP печатается один раз (браузер берёт первое вхождение, дубль молча отбрасывает): `sources` островов
  сливаются с директивой, в защитных (`object-src`, `base-uri`, `form-action`, `frame-ancestors`) — ошибка сборки.
  HTTP-набор читает CSP так же и сверяет источники с данными политики (`RESOURCE_ORIGINS`, `sources` включённых
  островов), а не с выходом механизма; `*` и `'unsafe-*'` запрещены и в политике.
- Идентификатор счётчика — атрибутом `data-counter`, а не `define:vars`: тело острова одно на любой счётчик,
  хеш не зависит от `METRIKA_ID`; что `init` идёт с идентификатором из разметки, держит тест в happy-dom.
- Источники счётчика — `https://mc.yandex.ru` в `script-src`, `connect-src`, `img-src`, только при `METRIKA_ID`
  (`on`); вебвизор, региональные домены и `wss:` — по списку Яндекса решением проекта, карта кликов
  (`frame-ancestors` кабинета) — правкой защитной директивы в политике и HTTP-наборе.
- `RESOURCE_ORIGINS` питает и CSP — `default-src`, `style-src` и каждую явную директиву загрузки: одна политика
  ресурсов для `seo:check` и браузера; в `script-src` её нет — внешних скриптов у сайта нет.
- `'self'` в `script-src` — умолчание Astro; пять хешей встроенных директив гидрации (`client:*`) Astro добавляет
  всегда — без хака не снять, пропускают они только собственные скрипты Astro, которых на страницах нет.
- CSP — заголовком (`staticHeaders`), а не `<meta>` (`frame-ancestors` в `<meta>` не действует). `_headers.json`
  адаптер читает по абсолютному пути сборки из `entry.mjs`: в образе он совпадает (`/app`, держит `accept:image`),
  копия HTTP-набора переписывает его на свой, а не найдя — не стартует: молча читались бы заголовки `dist/` репо
  (так выходит и при переезде каталога после сборки). `.dockerignore` пропускает политику — из неё конфиг строит CSP.
- Без CSP — ответы без страницы (файлы, crawler-файлы, тело 410, отказы формы), `500.html` с диска (бэклог
  `csp-error-page`) и дубль `<путь>/index.html` (заголовки сборки адаптер ищет по маршруту): его закрывает edge
  (`strip-index-html`, 301; приёмка — curl на `/about/index.html`), в приложении это был бы обход адаптера.
- Подбор записи `_headers.json` по вхождению пути (CSP у prerendered-страниц одна на все) — в rule `render-safety`,
  ссылкой — в `shared-ui` (scoped-стили): их читают правки конфига, `src/app` и UI, а план фазы удаляется.
- Политика читает `METRIKA_ID` из `shared/config/site.ts` (импорт там только типов, Node его снимает): условие
  острова живёт рядом с его источниками.
- Per-site идентификаторы (`METRIKA_ID`, `SITE_VERIFICATION`) — тип `string`; путь «задано» держит тест типа, а не
  вторая сборка в гейте: ломался он только типом, сайт с номером и токенами проходит гейт (`M/p2c/n5-metrika-on.log`).
- Заголовок безопасности ставит ровно один участник: дубль от приложения и edge дал бы два значения. Сторону
  приложения держит HTTP-набор — из заголовков безопасности оно ставит только CSP.
- `X-Frame-Options` не ставит никто — его заменяет `frame-ancestors 'none'`; `X-XSS-Protection` тоже: фильтра в
  браузерах нет, а в старых он сам открывал утечки.
- `Permissions-Policy` — `camera=(), microphone=(), geolocation=()` в общем `secure-headers`; сервису, которому они
  нужны, — свой headers-middleware (§ 1.6 handoff). `interest-cohort` не включён (Chrome предупреждает о неизвестной
  функции); COOP и CORP не вводятся: окон входа нет, а CORP закрыл бы встраивание картинок сайта.
- Роутер сайта на edge — `GET` и `HEAD`, `POST` — только форма: статик-хендлер отвечает на любой метод, `TRACE` —
  500 с ошибкой в логе; на edge это одно условие правила, в приложении — обход адаптера.
- Лимит chunked-тела формы — правдой, а не кодом: тело без длины до 64 КБ держит буферизация прокси, в процессе
  — `bodySizeLimit` 1 МБ; дочитывание тела со счётчиком дублировало бы контур, который edge уже закрывает.
- Origin-check назван антиспамом: у формы нет cookie и сессии, границы CSRF нет; чужой `Host` отсекает
  Host-роутинг edge. Требование «`X-Forwarded-*` обязателен» снято — приложение их не читает.
- Симлинки `public/` — правилом, а не проверкой: каталог под контролем автора, сборка симлинков не порождает.
- pnpm — без corepack: образ ставит `npm install -g` ровно версию `packageManager` (стадия `pnpm` общая для build
  и prod-deps), разработчик — `npm i -g pnpm@10`, точную версию pnpm подтягивает сам. Настройки —
  `pnpm-workspace.yaml` (`packages: [.]`, иначе каждый `package.json` в `docs/research` — проект и шум в гейте):
  `allowBuilds` вместо `onlyBuiltDependencies` (его pnpm 11+ молча не читает) — только пакеты со скриптами: esbuild
  и lefthook — да, unrs-resolver — нет (бинарник — optional-пакетом); `minimumReleaseAge` — 3 суток, окно снятия
  релиза в npm (pnpm 11+ сверяет с ним и lockfile). `.npmrc` удалён: hoist-ключи не нужны, реестр и токены приходят
  секретом `npmrc`.
- Строгие peer потребовали в S7 убрать `eslint-plugin-jsx-a11y` (peer `eslint ≤ 9`): a11y `.astro` держат 18 правил
  Biome `lint/a11y/*` и axe. Известный конфликт — строка `peerDependencyRules`: tsconfck Steiger объявляет TS ^5.
- `pnpm audit --prod --audit-level=high` — 0 без исключений: `http-cache-semantics` 4.3.0 (через astro) вне
  уязвимого диапазона GHSA-ch52-4w7c-c8xp (≤ 4.2.0), `auditConfig` нет; high dev-дерева (`braces` через
  `eslint-plugin-boundaries`) аудит релиза не смотрит — в образ оно не едет. sharp 0.35.5 — точный пин, вне диапазонов.
- `typecheck` — `astro sync && astro-check`: `astro check`, не загрузив чекер, выходит с 0 — гейт прошёл без типов
  (`M/p2c/check-s7.log`); бинарь чекера падает с 1 (`M/p2c/fail{open,closed}-astro-check.log`).
- Первый ежемесячный цикл — по процедуре политики: 17 прямых зависимостей — последние патчи и миноры своих мажоров,
  прошедшие выдержку (прод — `nodemailer` 10.0.14, `@sentry/node` 10.76.0); покрытие и `engines` не сдвинулись. Не
  вошли: моложе выдержки — Astro 7.3.6 и адаптер 11.1.7 (гейт на них зелёный), `@sentry/node` 10.76.1, `nodemailer`
  10.0.15, `typescript-eslint` 8.71.1, `lefthook` 2.1.17, `axe-core` 4.14.0; мажоры — не циклом, по таблице:
  `@sentry/node` 11, Steiger 0.7 с плагином 0.8 (у 0.x мажор — минор; `steiger` и `check:gate` зелёные, но дубли
  zod 3, TypeScript 5.9 и строка peer tsconfck остаются), `@types/node` 26 (в такт Node 24), js-yaml 5, TypeScript 7.
- Тесты `.astro` — разбором, а не подстрокой тега: dev-режим Vitest аннотирует теги (`data-astro-source-*`, Astro
  включает их с тулбаром), а выключать тулбар в тестах — подгонка под сырой HTML; подстрока остаётся для
  присутствия тега и отдельного атрибута.
- Мажор Node — `ARG NODE_VERSION`, умолчание 24 (Active LTS); на 26 — по политике после 2026-10-28, одной строкой.
  `accept:image` переносим на macOS: отказ ждёт опросом `docker inspect` до 20 с, а не `timeout`, время дренажа —
  `Date.now()` Node, а не `date +%s%N`; дренаж — по коду выхода и строке лога, контейнер staging поэтому без `--rm`.
- Автообновление — ежемесячная процедура в обвязке, а не Renovate: раннера и бота в экосистеме нет (CI нет, R15),
  конфиг без исполнителя обещал бы обновления, которых никто не делает. Напоминание — `/smartdev` по последнему
  коммиту `chore(deps)` с lockfile (новый пакет его не сдвигает), уязвимости — шаг `/release`. Политика — в форме
  `dependencies.md`: её копирует `/stack-deep-dive`, `/de-template` не трогает. Обновление — `pnpm up -L` и
  `pnpm add -E <пакет>@<версия>`: `<пакет>@<мажор>` pnpm пишет диапазоном. Исправление моложе выдержки —
  `minimumReleaseAgeExclude` с `<пакет>@<версия>` его и каждой свежей зависимости из отказа pnpm (у `@sentry/node`
  10.76.1 — ещё четыре): имя-шаблон с версией pnpm не принимает, а без версии он снял бы выдержку с семейства.
