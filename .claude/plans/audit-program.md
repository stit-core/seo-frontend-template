# audit-program — программа исправлений по аудиту: каждый угол ≥ 9 и сайт из пакета strategy

## Цель
Довести шаблон до ≥ 9/10 по каждому из 12 углов аудита и научить сайт собираться из того, что проектирует
strategy: слоя страницы, пакета дизайна и `ready.yaml`. Этот план — точка входа: порядок фаз, метод и решения
владельца; содержание работы — в планах фаз.

## Контекст
- **Аудит** (HEAD `0c5869c`, 2026-10-06): отчёт — https://claude.ai/artifact/PpN1W64Arfq9rRf3BUUZUM (Artifact
  `action: read`), локальная копия — `~/git/stit-core/stit-ssr-audit/audit-report.html`. Отчёты углов с
  `file:line`, экспериментами и рекомендациями — `~/git/stit-core/stit-ssr-audit/reports/<угол>.md`: `harness`,
  `code`, `tests`, `enforcement`, `seo`, `geo`, `security`, `perf`, `contract`, `stack`, `dogfood-diary`,
  `dogfood-mutations`. ID находок — `<угол>-NN` (`HAR`, `LIF`, `COD`, `TST`, `ENF`, `SEO`, `GEO`, `SEC`, `PRF`,
  `CON`, `STK`, `DOG`); решения — `R01…R28`.
- **Материалы** (`M` = `~/git/stit-core/stit-ssr-audit/`):
  - `BRIEF.md` — рубрика и правила экспериментов; семафоры `heavy.sh` (два тяжёлых прогона на машину) и
    `exclusive.sh` (порты и Docker — по одному);
  - `prompts.md` — промпты исполнителя, валидатора, фикса и перепроверки;
  - эксперименты аудита для приёмки: `tests/` (45 мутаций, `run_mutations.py`, прототипы тестов страниц
    `tests/prototypes/`), `enforcement/` (27 нарушений, `driver2.sh`, `matrix.txt`), `seo/` (6 SEO-нарушений),
    `security/` (атаки, `csp-variant-B.diff`), `dogmut/` (мутации кода догфудера);
  - отчёты валидаторов — `M/validation-<plan>-<этап>.md`.
- **Метод.** Дирижёр — главная сессия: код не пишет, запускает агентов и читает их короткие отчёты; подробности
  агенты пишут в файлы.
  - Этап — группа шагов плана фазы (`###` в «Шагах»). Исполнитель — свежий агент — делает шаги по порядку: шаг —
    отдельный коммит, план фазы обновляется тем же коммитом, перед коммитом — `pnpm check`.
  - Независимый валидатор этапа — свежий агент, не автор — воспроизводит проверки шагов и критерии в своём
    worktree, пишет отчёт и возвращает PASS или FAIL. FAIL → фиксы коммитами `fix(...)` → перепроверка тем же
    валидатором. Следующий этап — только после PASS.
  - Агенты передают работу друг другу через репо и материалы: план фазы («Решения», «Сделано:», «Где мы
    сейчас»), этот план, отчёты валидаторов. Каждый агент начинает с чистого контекста.
  - Одна пишущая рука на дерево репо; фазы в соседних репо идут параллельно своей рукой. Эксперименты — в
    worktree `M/wt-*`, в конце `git worktree remove --force`; `rm -rf` не используется.
  - Агенты владельца не спрашивают: решают здравым смыслом и пишут в «Решения»; то, что может решить только
    владелец, останавливает свою ветку работы.
  - План фазы пишется к началу её волны — по находкам аудита и итогам прошлых фаз.
- **Мутации и нарушения аудита** — мерило приёмки. Когда код переехал, мутация переносится на новое место с той
  же семантикой; когда механизм заменён решением владельца, она заменяется равносильной.
- **Push** (владелец): `main` — после закрытия каждого плана фазы, `pnpm check` зелёный на чистом дереве; в
  соседних репо — после закрытия своей фазы, их гейтом.

## Не входит

- Выкатка на VPS и живой домен: кабинеты Search Console, Вебмастера и Bing — работа проекта, не шаблона.
- Пилот `../pilot-greats` не меняется и не попадает в git шаблона: он — данные для приёмки стыка в worktree.

## Решения
- **Решения владельца (2026-10-06).** Приняты все рекомендации R01–R28 отчёта аудита; остальное агенты решают
  сами — так, чтобы шаблон был максимально грамотным, без вопросов владельцу; push — после закрытия каждого плана.
  - Вход сайта — слой страницы, факты и голос, пакет дизайна и `ready.yaml`; FSD-контракт сайта удаляется (R01);
    strategy — снимком с локом отпечатков (R02).
  - «0 JS по умолчанию; остров — только момент из спецификации движения или плана, с бюджетом уровня»; один
    остров предпочтений — тема и движение (R03). Тема и токены — на нейминге ДС, `data-theme` (R04); шрифты —
    Fonts API (R05); счётчики — после согласия (R06).
  - Блоки каталога — `widgets/<block-id>`, эталонный набор около 12 блоков (R07); тексты — данные по ключу
    `page/section/slot` (R08); локали 1…N (R09); блог — модуль, `/now` — рецепт (R10); слеш — из карты (R11);
    минимальный путь без strategy (R12).
  - HTTP-e2e — в гейте, браузерный e2e и ворота strategy — в `/release` (R13); покрытие 90 %, цель 95 % (R14);
    периметр — guard-хук и префлайт pre-push, CI нет (R15); пакет правок `docker/*` разрешён (R16); CSP в
    приложении, `/_image` закрыт на edge (R17).
  - Политика ИИ-ботов — поле сборки из брифа (R18); авторы без демо-автора (R19); карта и фиды из сборки (R20);
    теги индексируются от 3 записей (R21).
  - Доставка обновлений — `.template/`, `/upgrade`, теги `template/vX.Y.Z`; kinship удаляется (R22);
    `docs/research/**` — в архивный тег (R23); стек — pnpm без corepack, Node 26, TypeScript `~6.0`, политика
    обновлений (R24); политика ПДн шаблона — только без strategy (R25); форк на поверхность (R26).
  - Умолчания отчёта: цели касания 44 px; Prettier для `.astro` до стабилизации Biome; Steiger остаётся;
    IndexNow — скрипт в `/release`; `Clean-param` по умолчанию; заглавные в URL — 404; PNG-фавикон первым;
    `ask` в брифе → `allow-all`.
