# forms-consent-collections — форма-движок по набору strategy, согласие до счётчика, коллекции модулем

## Цель
Пятая фаза программы `audit-program` (P5), второй её план. Форма одна и жёсткая (имя, почта, сообщение; ошибка всегда
рисует контакты), ступени антиспама заперты в фиче, а в `shared/antispam` — шов капчи, который ничего не делает;
счётчик грузится без согласия; механика коллекции — копия на каждую коллекцию, блог вплетён в `shared` и скрипты
гейта. После плана форма собирается из набора `lead-forms.yaml`, который называет план страницы, повторяема и работает
без JS; счётчик стартует только после согласия в баннере по блоку `cookie-banner` каталога; коллекция — запись реестра,
схема и страницы на общем модуле, блог — такой же модуль.

## Решения
- Один обработчик для всех форм — `/api/contact` (на нём лимит edge `site-form` шаблона инфры): `form_id` —
  `<page-id>/<section-id>` из планов, белый список — формы страниц реестра маршрута (`formsOf`): строка — данные
  страницы с формой и проекция политики согласия, без композиции страницы. Тест маршрута проходит каждую форму планов
  снимка: страница с формой без строки реестра — красный.
- Ответ с ошибками — оболочка страницы формы (каркас её плана, мета с «Ошибка: », h1 — текст слота `seo.h1` плана) и
  секция своей формы с присланным: без JS человек видит, на какой он странице, свою форму, поля и сводку. Композиция
  страницы целиком тянула бы в серверный бандл данные секций без формы — у главной записи коллекции, `get-image` и
  `sharp` (`seo:check`, бюджет бандла), — а ответу они не нужны. Страница с формой без `seo.h1` — ошибка сборки с
  ключом; h1 каждой страницы — текст её `seo.h1` (тест страниц), поэтому заголовок ответа — заголовок страницы.
- Ответ без разобранной формы — отказы 403, 400, 413 и GET — на языке префикса пути `Referer` (`localeOf`), без него —
  на основном: тело ещё не прочитано, поля локали нет. GET — страница первой формы реестра на этом языке, без версии на
  нём — первой формы. Тексты отказов — строки словаря фичи (N13 валидатора P5-C): тест
  «текст страницы — данные» маршруты `/api/` не видит, их держит тест маршрута на каждой локали.
- Подписи полей и вариантов — словарь фичи по id на каждой локали сайта (словари симметричны, R09), `label` каталога —
  образец русской; тест — подпись каждого поля используемых наборов на каждой локали. Ключ из данных проверяет `has`
  словаря (`dictionary` из `shared/i18n`), строку даёт его `t`: на локалях теста словарь слайса подменяет
  `withTestLocales`, как и словарь сайта. Ошибки, сводка и отказы —
  микрокопия фичи; строки словаря фичи — данные теста «текст страницы — данные».
- Правила сервера — правила браузера: почта — `html5Email` (так проверяет `type="email"`, адрес на кириллическом домене
  браузер шлёт в punycode), длина текста — с переводом строки в один знак (так считает `maxlength`, а форма шлёт CRLF):
  строже браузера сервер отказал бы законной заявке, которую человек уже отправил.
- Лестница — `antispam.without_js` базы: ловушка — поле каталога `company-website`, rate-limit — edge; time-trap не
  делается — страница с формой из сборки, честной метки нет (K5); капча — решение проекта по логам атаки.
- Скрытые поля — `hidden_fields_without_js` базы: `form_id`, `page_url` пишет сборка, `variant` — у страницы с
  вариантами (в шаблоне нет), `utm_*`, `yclid`, `gclid` — сервер из query `Referer`; `landing_url` и `ym_client_id` у
  формы без JS нет.
- Версия согласия — дата редакции политики: факт слота `date` её плана (`policy-revision`), его формулировка — машинной
  даты у strategy нет (Handoff программы); `PRIVACY_POLICY_VERSION` уходит, дата одна — на странице политики и в записи
  согласия.
- Согласие — текст секции формы и ссылка на политику её версии по карте (`StrategyPage.policy`); строка словаря рядом с
  текстом согласия — склейка элементом, которую первый план оставил до движка, — уходит.
- `form.success: inline` плана — ошибка сборки с ключом секции: остров формы не делается, `unshown` — только успех
  формы, без JS это страница «спасибо» (N1 валидатора P5-B).
- Шов капчи и `CAPTCHA_*` удаляются (COD-08): ступени, которая ничего не делает, нет; в env шаблона инфры этих ключей
  нет (`compose/site.yml`) — Handoff не нужен.
- Ступени лестницы (S1) — функции `shared/antispam/ladder.ts`: `isTrustedOrigin`, `isTooLarge`, `readForm`, `isTrapped`
  (поле ловушки — аргумент: имя даёт набор формы). Порядок держит обработчик формы и пишет событие отказа в лог:
  ловушка стоит после разбора формы и локали, функции «лестница целиком» нет. Матрица враждебных Origin и Referer,
  граница 64 КБ, тело не формы — тест ступеней; тест обработчика — композиция: исход каждой ступени без доставки, тело
  больше лимита не читается, ни на одном исходе в логе нет ни ответа на поле набора, ни query `Referer`.
- Обоснование `checkOrigin` и лимита тела адаптера — только rule `forms-antispam` (COD-13): у `astro.config.ts` и
  ступени — строка со ссылкой на правило, rule `render-safety` — ссылка; эссе middleware сжато до строки.
- Тестовых параметров в API нет (COD-14): `log(level, fields)`, `deliverLead(lead)`, контекст обработчика — `rid`; env
  тестов — `vi.stubEnv`, паузы повторов — fake timers (`vi.runAllTimersAsync`).
- Капчи нет ни ступенью, ни ключом env, ни строкой словаря; провайдер — решение проекта по логам атаки (норма базы
  `antispam.captcha`) вместе со своей ступенью и тестом — так и в rule `forms-antispam`.
- Чтение формы (S2) — `shared/strategy`: действие с `form` — значение `LeadForm` (`form_id` — `<страница>/<секция>`, набор
  каталога по `form.ref` полями схемы чтения `LeadFormsSchema`, ловушка и метки сервера из `defaults` каталога, страница и
  «спасибо» на языке страницы); набор, который форма без JS не соберёт (набора нет, `success: inline`, согласие не
  галочкой, `marketing_consent` без своего текста, шаги, поле файла, варианты не списком), — ошибка с ключом действия.
  Каталог в бандле — проекция схемой плагина `yaml-modules`. Поддержаны виды `text`, `textarea`, `email`, `tel`, `radio`.
- Варианты канала связи (`contact-channel`) — только каналы, которые бизнес ведёт (норма каталога): звонок и почта — факты
  с `machine` `telephone` и `email`, мессенджер — факт `messenger` своей сети; без каналов поля нет. Вариант канала без
  факта обещал бы ответ, которого бизнес не даст; выбор без вариантов не ответить, а без поля ответ — звонком (`why`
  каталога); обязательным это поле не делает ни один набор каталога. Почта — ещё и только у набора с полем почты: без
  адреса ответить письмом некуда (`consultation-request`, `quote-request` спрашивают телефон).
- Готовое сообщение мессенджера — параметр `text` адреса ссылки действия (wa.me, t.me): формат по сети база не задаёт;
  текст слота `messenger-prefill` — вид `unshown` (тест контракта пускает его и на этот слот). Блоки `lead-form`,
  `thank-you`, `contact-details` принимают мессенджер своей анатомии, ссылка канала показывает свой адрес (`channelText`).
- Политика согласия — `policyOf(page, проекция политики)`: версия по карте, заголовок документа (`seo.h1` её плана) и дата
  редакции — факт, который план политики связывает с датой (`binds: [date]`). Проекция — модуль
  `virtual:strategy/consent/<политика>` (`consentOf`, `contract.ts`): адрес, заголовок по языкам copy deck и ссылка на факт;
  её собирает на сборке плагин `yaml-modules` из плана, copy deck и карты, поэтому план и тексты политики в серверный
  бандл ответа формы не едут, а правило `seo:check` о данных on-demand страниц верно как есть: пути плана в проекции нет.
  Ссылка согласия — отдельный элемент под галочкой, подписан заголовком документа на его языке (`lang`, `hreflang`); тест
  «текст страницы — данные» судит участок с `lang` данными его языка. На странице языка, где версии политики нет, ссылка
  ведёт на версию другого языка и подписана её заголовком на нём: подписи ссылки в анатомии блока `lead-form` нет, строка
  словаря рядом с текстом секции — склейка, а заголовок на языке страницы назвал бы документ, которого на нём нет;
  версия политики на языке страницы (copy deck и строка карты) даёт ссылку на нём без правки кода.
- Форма-движок — `features/lead-form` (путь шаблона в `.template/paths`): словарь фичи (`config/dict.ts` — данные без кода,
  их читает и браузерный набор; `t` — `dictionary()` из `shared/i18n`, `lib/text.ts`), правила набора на сервере
  (`model/schema.ts`: обязательные, вид и длина — 200, 2000, 254, телефон 10–15 цифр, вариант из списка,
  `one_of_required`, согласие `literal(true)`), обработчик по `form_id` и `page_url` (форма плана на версии своей
  страницы, иначе 400; локаль — версия страницы), заявка — ответы набора, метки рекламы из query `Referer` и запись
  согласия `defaults.consent.record`. Метки обязательности — у меньшей группы (`minority-rule`). `form.*` ушли из
  `shared/i18n`, `PRIVACY_POLICY_VERSION` снят.

- Согласие и счётчик — один остров (строка счётчика `ISLANDS`, `app/analytics`): баннер печатается скрытым и
  открывается островом, пока выбора нет; выбор — `localStorage`, cookie сайт не ставит; «Отклонить» — кнопка того же
  вида, что «Принять». Цели — визит «спасибо» (у формы свой адрес) и автоцели счётчика, своего кода целей нет
  (`events.yaml#defaults.without_js`).
- Строка острова — `metrika` (её имя знают мутации эталона и трек P8), разметка (`markup`) — `data-consent-banner` и
  `data-consent`: баннер на странице без острова — нарушение `seo:check`, оболочка ставит их одним условием — строкой
  счётчика. Выбор — ключ `consent`, «accept» или «reject» со временем выбора; действует год (вариант «согласие» базы,
  GOV.UK), старше года или не из словаря острова — баннер снова; закрытое хранилище оставляет выбор странице; страница
  из кеша «назад» перечитывает выбор. Счётчик после «Принять» — прежний загрузчик после простоя, один раз; идентификатор
  — проп `counter` острова (оболочка даёт `METRIKA_ID`), чтобы мини-сборка браузерного набора поставила свой.
- Вариант баннера — `in-flow-top` каталога: до шапки, сразу после перехода к содержимому. GOV.UK ставит баннер и до
  перехода, но axe признаёт переход, только пока он — первая ссылка страницы (`region` браузерного набора). Клавиатура
  встречает баннер раньше страницы, фокус он не закрывает (WCAG 2.4.11) без замера высоты и `scroll-padding`, после
  выбора Tab идёт к следующей цели по порядку — своего кода фокуса у острова нет; открывается кадром разбора до
  отрисовки, сдвига вёрстки нет. Область — `<section aria-label>`: та же роль region, что `div role=region` каталога (Biome
  `useSemanticElements`). Фон без тона, черта — как у шапки: новых пар контраста нет.
- Ссылка баннера — политика ПДн плана каркаса (`legal.privacy_policy`, версия по карте с `hreflang`); счётчик у плана
  каркаса без неё — ошибка сборки с ключом. Подпись — строка словаря `consent.policy`: все тексты баннера — микрокопия,
  склейки с copy deck нет, как у правовых ссылок подвала (копию политики `virtual:strategy/consent/<id>` оболочка по
  адресу не найдёт: модуль — по id страницы). Планы проекта теста, которые рисует оболочка (список, запись, тег блога),
  называют политику, как планы сайта: у форка со счётчиком тест страниц блога иначе падал бы этой ошибкой.
- C-05 — браузерный набор `consent.spec.ts` на мини-сборке (остров, баннер, стили сайта) с CSP заголовком из строки
  счётчика реестра: остров исполняется по хешу, счётчик — с origin `sources`, запросы к нему перехватывает тест. Тот же
  файл держит отказ, повтор визита, страницу без JS, клавиатуру, axe в каждой теме и высоту баннера на телефоне (норма
  каталога — до 30 % экрана); страницы сборки сайта — баннер только при `METRIKA_ID`, запросов к счётчику до выбора нет.
- Баннер — разметка по анатомии и семантике блока `cookie-banner` каталога (область с подписью, немодальный: текст,
  «Принять», «Отклонить», ссылка на политику ПДн) рядом с островом в `app/analytics`, а не блок `widgets`: текстов
  оверлея у copy deck 0.2.2 нет (COPY-D-PLAN), а оверлея у планов шаблона нет (бриф — `cookie_banner: none`, тест
  контракта блока «на будущее» не пускает). Тексты — микрокопия согласия в словаре, как подписи переключателей темы;
  оверлей плана и его тексты copy deck — P8 и strategy (Handoff).
- Модуль коллекций — сегмент `shared` (серверный, под тестами); слайс коллекции — схема, контент, карточка, подписи
  тегов; реестр — одна запись на коллекцию, скрипты читают её листовым модулем; `astro:content` вне модуля — `lint`.
  Записи перечисляются только на языках маршрута шаблона записи (`pageLocales(<шаблон>)`): у несобранного шаблона P8
  маршрута нет — нет и карточек (Handoff P8).
- Подписи тегов — данные коллекции в слайсе по локалям (записи — вне слоя strategy); тег без подписи — ошибка сборки.
  Строки блога (фид, страницы 2…N, тег) — в слайсе, подписи блоков (`article-cards` — навигация и пустой список,
  `article-body` — термины и теги) — ключи блоков в `shared/i18n`: блок служит любой коллекции. Строки слайса — данные
  теста «текст страницы — данные».
- Ссылка autodiscovery на фид — только на страницах блога: правило «на каждой странице» уходит (COD-03, LIF-04).
- Скрытый текст записи (`hidden-built`) — правило `seo:check` на собранной странице записи: текст тела, которого браузер
  не покажет (`<template>`, `<noscript>`, `<dialog>` без `open`; цвет и SVG — где их видно без CSS), — нарушение.
  `check:content` ловит атрибуты до сборки, а тест «текст страницы — данные» вычитает тело записи целиком (приёмка P5a).
- Сводка ошибок движка — внутри условного выражения разметки, как у текущей формы: Biome `noAutofocus` строчный
  `autofocus` в выражении не узнаёт, смысл правила держит ESLint (только у `role="alert"`); вынос сводки наверх потребовал
  бы исключения в конфиге линтера — это решение владельца (валидатор P4-B, N5).
- Пустое тело записи — ошибка `check:content` любой коллекции, с фикстурой (DOG-03).
- Вторая коллекция — сценарий приёмки: «Кейсы» ветки догфудера на модуле в worktree — код, строки карты, планы и copy
  deck списка и записи; в `main` не идут (R28).
