# forms-consent-collections — форма-движок по набору strategy, согласие до счётчика, коллекции модулем

## Цель
Пятая фаза программы `audit-program` (P5), второй её план. Форма одна и жёсткая (имя, почта, сообщение; ошибка всегда
рисует контакты), ступени антиспама заперты в фиче, а в `shared/antispam` — шов капчи, который ничего не делает;
счётчик грузится без согласия; механика коллекции — копия на каждую коллекцию, блог вплетён в `shared` и скрипты
гейта. После плана форма собирается из набора `lead-forms.yaml`, который называет план страницы, повторяема и работает
без JS; счётчик стартует только после согласия в блоке `cookie-banner`; коллекция — запись реестра, схема и страницы на
общем модуле, блог — такой же модуль.

## Решения
- Один обработчик для всех форм — `/api/contact` (на нём лимит edge `site-form` шаблона инфры): `form_id` —
  `<page-id>/<section-id>` из планов, белый список собирается на сборке; ответ с ошибками рисует композицию исходной
  страницы (`src/pages/_<page-id>/`) с состоянием формы — без JS человек видит свою страницу, поля и сводку.
- Подписи полей: русская — `label` каталога, другие локали — словарь фичи по id поля (у каталога подпись одна);
  тест — подпись каждого поля используемых наборов на каждой локали. Ошибки и сводка — микрокопия фичи.
- Лестница — `antispam.without_js` базы: ловушка — поле каталога `company-website`, rate-limit — edge; time-trap не
  делается — страница с формой из сборки, честной метки нет (K5); капча — решение проекта по логам атаки.
- Скрытые поля — `hidden_fields_without_js` базы: `form_id`, `page_url` пишет сборка, `variant` — у страницы с
  вариантами (в шаблоне нет), `utm_*`, `yclid`, `gclid` — сервер из query `Referer`; `landing_url` и `ym_client_id` у
  формы без JS нет.
- Версия согласия — дата редакции политики (слот `date` её copy deck): поле `PRIVACY_POLICY_VERSION` уходит, дата одна
  на странице политики и в записи согласия.
- Шов капчи и `CAPTCHA_*` удаляются (COD-08): ступени, которая ничего не делает, нет; в env шаблона инфры этих ключей
  нет (`compose/site.yml`) — Handoff не нужен.
- Согласие и счётчик — один остров (строка `ISLANDS` счётчика): баннер печатается скрытым и открывается островом, пока
  выбора нет; выбор — `localStorage`, cookie сайт не ставит; «Отклонить» — кнопка того же вида, что «Принять». Цели —
  визит «спасибо» (у формы свой адрес) и автоцели счётчика, своего кода целей нет (`events.yaml#defaults.without_js`).
- Модуль коллекций — сегмент `shared` (серверный, под тестами); слайс коллекции — схема, контент, карточка, подписи
  тегов; реестр — одна запись на коллекцию, скрипты читают её листовым модулем; `astro:content` вне модуля — `lint`.
- Подписи тегов — данные коллекции в слайсе по локалям (записи — вне слоя strategy); тег без подписи — ошибка сборки.
- Ссылка autodiscovery на фид — только на страницах блога: правило «на каждой странице» уходит (COD-03, LIF-04).
- Сводка ошибок движка — внутри условного выражения разметки, как у текущей формы: Biome `noAutofocus` строчный
  `autofocus` в выражении не узнаёт, смысл правила держит ESLint (только у `role="alert"`); вынос сводки наверх потребовал
  бы исключения в конфиге линтера — это решение владельца (валидатор P4-B, N5).
- Пустое тело записи — ошибка `check:content` любой коллекции, с фикстурой (DOG-03).
- Вторая коллекция — сценарий приёмки: «Кейсы» ветки догфудера на модуле в worktree, в `main` не идут (R28).
