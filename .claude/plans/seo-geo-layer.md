# seo-geo-layer — SEO и GEO: одна сущность, авторы, политика ИИ-ботов, карта из сборки, Яндекс

## Цель
Третья фаза программы `audit-program` (P3). Страница готова к поиску и ИИ-ответам, слоя вокруг неё нет: организация —
две сущности без `@id`, авторов нет, политика ИИ-ботов — env с неполным списком, карта — ручной список, тонкие теги в
индексе, Яндекс неполон, адреса миграции не выражаются, неканоническая форма адреса даёт дубль или второй хоп,
`geo_probe` не зовёт никто. После фазы слой собирается из данных и держится машиной: SEO- и GEO-мутации ловит гейт.

## Решения
- Граф — отдельные блоки JSON-LD со ссылками по `@id`, не `@graph`: `seo:check` читает верхний `@type` блока, ссылка
  несёт `@type`, `@id` и `name` — блок самодостаточен и без узла организации на странице (GEO §5 B). `@id` —
  `<origin>/#org` и `/#website`; `LocalBusiness` «О компании» — тот же `@id`; размещение по типам страниц — P5.
- Авторы (R19): реестр `entities/author` в шаблоне пуст, поле `author` проверяет схема коллекции — её читают и сборка, и
  `check:content`; тесты и фикстуры гейта — на фикстурном авторе вне контента. `@id` автора стабилен на своём origin.
- Реестр ИИ-ботов — копия файла `crawlers.yaml` базы strategy байт в байт в `shared/seo`: сборка читает из неё
  `policies` (группу с `Disallow: /` своей политики) и мету `deny-all`; правка — заменой файла, сверку sha256 с соседом
  делает `/seo-audit`, снимок P8 забирает файл себе. Норма одна и у владельца — базы; рукописный список в TS — вторая
  копия, которая расходится молча (GEO-02); P6 уже числит `crawlers` в снимке сайта для `ai_bots_policy`. Ожидания
  матрицы — не из проверяемой группы: обучающие (`bots[].purpose`) закрыты во втором режиме, классика открыта везде.
- Политика — поле сборки `site.ts` (R18): ревьюится в git, одна на все среды, доходит до `<head>` prerendered (мета
  `deny-all`); `ROBOTS_POLICY` staging — runtime, поэтому `robots.txt` остаётся on-demand.
- Карта — файл сборки по выходу `dist/client` (хук `astro:build:done` локальной интеграции, как `closedImageEndpoint`;
  в рамках R20), не эндпоинт со списком: страница без `noindex`, `loc` — её canonical, `lastmod` — её `article:*_time`.
  Карта равна страницам по построению, в `astro dev` её нет; фиды — prerendered; `X-Robots-Tag` им не нужен (прил. А).
- `lastmod = updatedDate ?? pubDate` (GEO-07): у неправленой записи дата публикации и есть дата последнего изменения.
  MUT-11 аудита заменена равносильной MUT-11′ — «`lastmod` только из правки или дата сборки».
- Теги: порог — константа коллекции (3, R21); страница ниже порога собирается — ссылки на неё живые — и закрыта
  `noindex`; право на `noindex` ей `seo:check` берёт из источника, а не из `NOINDEX_ROUTES`.
- Один хоп — в обёртке `docker/server.mjs`, единственном месте до статик-хендлера (как заголовок staging P2): GET и HEAD
  неканонической формы (хвостовой слеш, `//`, `/index.html`, точки) — один 301 на «правило таблицы или канон»; таблица —
  тот же модуль серверной сборки, что у middleware (как `runtime-config.mjs`); форма слеша — одна настройка сборки
  (R11 правит её в одном месте). `strip-index-html` на edge снят: дубль закрывает обёртка, держит HTTP-набор. Правка
  `docker/*` — по R16 и решению владельца «агенты решают сами».
- Миграция: `from` — любой путь старого сайта, точное совпадение с регистром (заглавные своих адресов — 404, умолчание
  программы); кириллица и проценты — к одной закодированной форме; `?query` в `from` срабатывает при всех его парах, они
  в `Location` не переносятся, прочие — переносятся; «без цепочек» сохраняется. Закодированный слеш (`%2F`, `%5C`) — 404.
- 404 и 410 — локаль из префикса пути; 500 — дефолтная: файл с диска запроса не знает.
- `Clean-param` — список `CLEAN_PARAMS` в `site.ts` (умолчание программы), строкой прод-robots; staging — без неё.
- IndexNow: ключ остаётся runtime env (контракт env не меняется), скрипт получает его аргументом и сверяет с живым
  файлом ключа; дифф — карта, снятая `/release` до handoff, против живой после выката. Без ключа шаг пропускается строкой.
- GEO-текст: машина держит структурное — скрытая разметка в теле (`style=`, `hidden`, `aria-hidden`), даты, автор;
  `style=` в теле записи — ещё и нарушение CSP страницы (инлайн-стиль), которое без этой проверки видит только
  браузерный набор (хвост P2). Словари фраз — `copy_lint.py` базы в `/content`, в шаблон не копируются (G-03,
  G-04 — объяснённые выжившие).
- UA-матрица — в HTTP-наборе гейта, боты — поисковые и user-fetch записи копии `crawlers.yaml`: ответ ботам — HTTP.
- Контракт edge: allowlist — по спискам вендоров (`ip_list_url`, `rdns_suffix` записей `crawlers.yaml`), не по UA;
  обучающие — по политике (при `allow-all` в allowlist и CCBot); значение политики печатает handoff `/release`.
- `geo_probe` — шаг `/seo-audit`, не гейт (внешний Python и сеть); флаги, ожидаемые политикой, — не дефект.
- Не делается: `llms.txt` (база, Google 2026-06-15 — «neither harm nor help»; `/llms.txt` — 404 `text/plain`),
  Markdown-двойники, `Content-Signal`/`Content-Usage` (черновики без поддержки ботами; за Cloudflare — согласовать с
  политикой, `crawlers.yaml rt-cdn-waf`), время и зона в датах разметки (в источнике их нет), `SITE_VERIFICATION.bing`
  (BWT подтверждает импортом из Search Console, файлом или DNS), скрипт отчёта по ботам (рецепт `jq` в `observability.md`).
