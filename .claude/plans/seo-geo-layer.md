# seo-geo-layer — SEO и GEO: одна сущность, авторы, политика ИИ-ботов, карта из сборки, Яндекс

## Цель
Третья фаза программы `audit-program` (P3). Страница готова к поиску и ИИ-ответам, слоя вокруг неё нет: организация —
две сущности без `@id`, авторов нет, политика ИИ-ботов — env с неполным списком, карта — ручной список, тонкие теги в
индексе, Яндекс неполон, адреса миграции не выражаются, неканоническая форма адреса даёт дубль или второй хоп,
`geo_probe` не зовёт никто. После фазы слой собирается из данных и держится машиной: SEO- и GEO-мутации ловит гейт.

## Контекст
- Программа, метод и решения владельца — `audit-program.md`: R18 (политика ИИ-ботов — поле сборки, списки 1:1 из
  `crawlers.yaml`, env `AI_TRAINING` удаляется), R19 (авторы без демо-автора), R20 (карта и фиды из сборки), R21 (теги от
  трёх записей); умолчания — IndexNow-скрипт в `/release`, `Clean-param` по умолчанию, заглавные в URL — 404, PNG-фавикон
  первым, `ask` → `allow-all`. Код — после P2 `harden-runtime`: обёртка `docker/server.mjs` (заголовок staging),
  модуль сборки `runtime-config.mjs`, локальная интеграция `closedImageEndpoint` в `astro.config.ts`.
- Находки — `~/git/stit-core/stit-ssr-audit/reports/`: `seo.md` SEO-01…14, `geo.md` GEO-01…09, хвосты других углов. Куда ушла
  каждая (шаг P3, другая фаза, закрыта, отклонена) и набор мутаций приёмки — `M/plans/seo-geo-layer.coverage.md`.
- Нормы — база strategy (`<strategy-path>/.claude/skills/design-deep-dive/`): `kb/site/07-…/crawlers.yaml` (боты,
  `policies`, `rt-*`), `head-kit.yaml` (`jsonld_policy`, `recipes`, `yandex`), `kb/text/07-seo-geo-copy/geo-checklist.yaml`;
  утилиты `scripts/site/geo_probe.py`, `scripts/text/copy_lint.py` в окружении `~/.cache/design-deep-dive/venv`. Свежий
  `crawlers.yaml` — P6 S2 (ветка `p6-strategy-contract`, `M/wt-p6`), пока P6 не влит в `main` strategy.
- Эксперименты приёмки (`M` = `~/git/stit-core/stit-ssr-audit/`): `M/seo/scripts/`, `M/geo/`, диффы SEO-нарушений P1 —
  `M/acc/s8/`, мутации эталона — `M/tests/mutations.py`. Мутации набора — по колонке «шаг» файла покрытия (§ 5): шаг
  переносит сдвинутые с той же семантикой и проверяет, что свои мутации красные.
- Сквозные правила шагов: новое правило `seo:check` или `check:content` — с негативной фикстурой `.gate-fixtures` и
  строкой `expected.json`; новая проверка HTTP-набора — с мутацией, которую она краснит; новый код `src` — с тестами в
  храповике покрытия; локали — из `SUPPORTED_LOCALES`, не парой `ru`/`en` (P5 — 1…N); проза — тем же коммитом.

## Не входит
- P4: обложки нескольких пропорций и вес OG-картинки, иконки из пакета бренда (правило «PNG первым» остаётся).
- P5: типы JSON-LD страниц по `head-kit` поверх графа P3 (`ContactPage` + `LocalBusiness` контактов, `AboutPage`,
  `CollectionPage`, `Service`, `ProfilePage` автора), крошки с глубины 2 и блок «связанные», подписи тегов по локалям,
  ссылки 404 на хабы, `/now` из подвала (R10), ссылка на фид со страниц блога, i18n на 1…N локалях.
- P7: CrowdSec, Traefik и access-log в шаблоне инфры — здесь контракт в `docs/reference/infra-handoff.md`.
- P8: бриф (`search.ai_bots_policy`, `profiles`, `ai_answers`) и факты (`machine`: часы, гео, реквизиты), снимок strategy,
  ворота `page_gates.py` в `/release`, один источник идентичности (COD-11, CON-13).
- `llms.txt`, Markdown-двойники, `Content-Signal`/`Content-Usage`, WebMCP — решение отчёта GEO §5 H и базы.

## Решения
- Граф — отдельные блоки JSON-LD со ссылками по `@id` (`<origin>/#org`, `/#website`), не `@graph`: ссылка несёт
  `@type`, `@id` и `name` — блок самодостаточен и без узла организации на странице (GEO §5 B); размещение по типам
  страниц — P5. `seo:check` узнаёт организацию по типу узла на любой глубине и сверяет имя между страницами.
- Авторы (R19): реестр `entities/author` в шаблоне пуст, тесты и фикстуры гейта — на фикстурном авторе. Схема и
  статья реестр не импортируют (соседний слайс): id авторов — контекстом схемы, подпись — слотом статьи. `@id` —
  `/#author-<id>`, один на локали; имя и роль — по локалям, «одно имя у `@id`» — в пределах локали; `url` — P5.
- Реестр ИИ-ботов — копия файла `crawlers.yaml` базы strategy байт в байт в `shared/seo`: сборка читает из неё
  `policies` (группу с `Disallow: /` своей политики) и мету `deny-all`; правка — заменой файла вместе с sha256 в
  политике сборки (`CRAWLERS_SHA256`: правку руками валит `pnpm test`), сверку с соседом делает `/seo-audit`, снимок
  P8 забирает файл себе. Ожидания матрицы — не из проверяемой группы: обучающие (`bots[].purpose`) закрыты во втором
  режиме, классика открыта везде.
- Политика — поле сборки `site.ts` (R18): ревьюится в git, одна на все среды, доходит до `<head>` prerendered (мета
  `deny-all`); `ROBOTS_POLICY` staging — runtime, поэтому `robots.txt` остаётся on-demand. Группа `*` у сайта своя и
  открыта при любой политике: `accept:image` и HTTP-набор сверяют её, а не отсутствие `Disallow` во всём файле.
- Карта — файл сборки по выходу `dist/client` (хук `astro:build:done` локальной интеграции; в рамках R20), не
  эндпоинт со списком: страница без `noindex`, `loc` — её canonical, `lastmod` — её `article:*_time`; в `astro dev`
  карты нет, фиды — prerendered. Генератор — `scripts/lib/sitemap.mjs` рядом с политикой сборки, формат —
  `shared/seo/sitemap.ts`. `seo:check` считает ожидаемую карту независимо от генератора: адрес — от пути страницы,
  дата — из frontmatter. Цели фидов HTTP-набор берёт по имени маршрута, а не по режиму.
- `lastmod = updatedDate ?? pubDate` (GEO-07): у неправленой записи дата публикации и есть дата последнего изменения.
  MUT-11 аудита заменена равносильной MUT-11′ — «`lastmod` только из правки или дата сборки».
- Теги: порог — константа коллекции (3, R21); страница ниже порога собирается — ссылки на неё живые — и закрыта
  `noindex`; право на него `seo:check` берёт из источника, а не из `NOINDEX_ROUTES`. Порог записан дважды — в
  коллекции и в политике сборки: расхождение чисел или сдвиг порога в коде — красный. Перевод тега — страница другой
  локали от порога: тонкая страница ссылку на индексируемую пару в шапке несёт, обратной ссылки и hreflang нет.
- Один хоп — в обёртке `docker/server.mjs`, единственном месте до статик-хендлера: GET и HEAD неканонической формы
  (хвостовой слеш, `//`, `/index.html`, точки, запись процентов) — один 301 на «правило таблицы или канон»; таблица —
  тот же модуль серверной сборки, что у middleware; форма слеша — одна настройка сборки `TRAILING_SLASH` (R11 правит
  её в одном месте). Правка `docker/*` — по R16. Обёртка отвечает на переезд и в канонической форме адреса: правило
  с `?query` на пути живой страницы (`/?p=123`) статик-хендлер перекрыл бы страницей. 410 остаётся приложению
  (страница, лог, `X-Request-Id`): 410 на пути живого маршрута — ошибка `check:content`, отвечает одна форма
  удалённого адреса — каноническая. Middleware считает канон по адресу запроса, а не по `context.url`: Astro
  раскодирует путь по-своему — вышла бы петля.
- Форма адреса за edge (N1 валидатора B): `strip-index-html` на edge снят — хвостовой слеш, `/index.html` и адреса
  таблицы Traefik передаёт как есть, их закрывает обёртка. `//`, сегменты `.` и `..` и букву процентами Traefik
  приводит сам до проксирования (`sanitizePath` — умолчание безопасности entryPoint, общего для сервисов; контракт его
  не выключает): по такому адресу за edge — страница 200. Дубль закрыт canonical и тем, что ссылку неканонической
  формы валит `check:links`; приёмка инфры проверяет 301, 404 на `%2F` и canonical на `//about`.
- Миграция: `from` — любой путь старого сайта, точное совпадение с регистром (заглавные своих адресов — 404);
  кириллица и проценты — к одной закодированной форме; `?query` в `from` срабатывает при всех его парах, они в
  `Location` не переносятся, прочие — переносятся. Закодированный слеш (`%2F`, `%5C`) — 404 текстом. Внешняя цель —
  в одной ASCII-записи (`new URL().href`). Демо-правила шаблона показывают формы миграции — на них HTTP-набор и ходит.
- 404 и 410 — локаль из префикса пути; 500 — дефолтная: файл с диска запроса не знает. Локаль адреса — одна функция
  `localeOf` (`shared/i18n`): её же читают `seo:check` и HTTP-набор. Язык в теле страницы ошибки один.
- `Clean-param` — список `CLEAN_PARAMS` в `site.ts` (умолчание программы), строкой прод-robots; staging — без неё.
- IndexNow: ключ остаётся runtime env (контракт env не меняется), скрипт получает его аргументом и сверяет с живым
  файлом ключа; дифф — карта, снятая `/release` до handoff, против живой после выката. Без ключа шаг пропускается строкой.
- GEO-текст: машина держит структурное — скрытая разметка в теле (`style=`, `hidden`, `aria-hidden`), даты, автор;
  `style=` в теле записи — ещё и нарушение CSP страницы (инлайн-стиль), которое без этой проверки видит только
  браузерный набор (хвост P2). Словари фраз — `copy_lint.py` базы в `/content`, в шаблон не копируются (G-03,
  G-04 — объяснённые выжившие).
- UA-матрица — в HTTP-наборе гейта: каждый бот копии `crawlers.yaml`, который ходит в сеть (кроме `control-token`),
  × шаблон каждой страницы, on-demand маршрут, карта, фиды, адрес без страницы, адреса `redirects.yaml` и ответы
  обёртки. «Тот же ответ» — статус, тело и все заголовки, кроме `Date` и `X-Request-Id` (у `/now` тело живое).
- Контракт edge для ботов: allowlist — по спискам вендоров (`ip_list_url`, `rdns_suffix` записей `crawlers.yaml`), не
  по UA; обучающие — по политике. Политику инфра читает с живого `robots.txt`, строки печати хранит файлом своего
  репо; `AI-BOTS` handoff `/release` называет политику и версию реестра.
- `seo:check` читает то же, что поисковик: блок JSON-LD — любой `<script>` этого типа, видимое — без поддеревьев
  `hidden` и `aria-hidden`, микроданные — ошибка; `ORG_TYPES` — список политики, узел с `@id` организации другого
  типа — ошибка. Обратного правила «подпись без `Person`» нет: у подписи нет машинного признака до ссылки
  `rel="author"` на профиль (P5).
- Пороги покрытия пересчитывает коммит шага, который меняет объём кода `src` (rule `tests-pipeline § Покрытие`).
- `geo_probe` — шаг `/seo-audit`, не гейт (внешний Python и сеть); флаги, ожидаемые политикой, — не дефект.
- Не делается: `llms.txt` (база, Google 2026-06-15 — «neither harm nor help»; `/llms.txt` — 404 `text/plain`),
  Markdown-двойники, `Content-Signal`/`Content-Usage` (черновики без поддержки ботами), время и зона в датах
  разметки, `SITE_VERIFICATION.bing` (BWT подтверждает импортом из Search Console, файлом или DNS), скрипт отчёта по
  ботам (рецепт `jq` в `observability.md`).

  `sanitizePath` entryPoint не выключается — `//`, точки и букву процентами edge приводит сам (за ним 200 с canonical).
