# Тесты

## Расположение и проекты Vitest

- Любой тест-файл `src/**/*.{test,spec}.{ts,mts}` запускается, а `.only` — ошибка прогона
  (`allowOnly: false`): тест не выпадает из гейта молча
- **Unit** — рядом с модулем (`shared/i18n/locale.test.ts`): проект `dom` (happy-dom)
- **Компонентные `.astro`** — `<name>.astro.test.ts` рядом с компонентом: проект `astro`
  (node-окружение, Container API `experimental_AstroContainer`); разметка сверяется разбором —
  элементы, атрибуты и текст через `parseHtml` из `@/shared/lib/testing` (`<head>` страницы —
  `headTags()`, тот же парсер, что у `seo:check` и e2e), а не подстрокой тега: в dev-режиме
  Vitest Astro добавляет к тегам `data-astro-source-*`, и патч фреймворка не должен краснить
  гейт; подстрока годится для присутствия (`'<script'`) и отдельного атрибута. Плюс
  `expectNoA11yViolations` оттуда же (axe-core; правило `region` для
  фрагмента выключено; в happy-dom нет CSS — контраст видит только браузерный набор
  `e2e/browser/a11y.spec.ts`). Пропсы-сущности — плоские фикстуры (`Post` не тянет `astro:content`)
- **Запросы к контенту** (`entities/*/api/queries.test.ts`) — `astro:content` подменяется
  `vi.mock` с фикстурами через `vi.hoisted`, модуль импортируется после мока: проверяются
  фильтр черновиков и локали, сортировка, twin по `translationKey` — в обоих режимах
  (`vi.stubEnv('DEV', false | true)`: Vitest сам работает в dev-режиме Vite)
- **Серверные и процессные** — `<name>.server.test.ts`: проект `astro` (node-окружение, родные
  `Request`/`Response`): `app/middleware` с подменённым `getRuntimeConfig` (`vi.mock`
  `@/shared/config`) и `next`-заглушками; `docker/*` гоняется через `spawnSync` с таймаутом —
  зависший процесс роняет тест, а не подвешивает гейт (fail-fast `server.mjs`, отказ, штамповка
  и `exec` `entrypoint.sh` на временном `dist`); перехват исключения слушателя и ответ на адрес —
  на живой обёртке с заглушками адаптера и таблицы адресов: срок на подъём, тест гасит процесс сам
- **Маршруты и страницы** — `src/pages/_tests/` (каталог с `_` Astro не маршрутизирует):
  эндпоинты вызываются напрямую (`endpoints.server.test.ts`), страницы рендерит Container API
  целиком (`partial: false`), а где важны статус и заголовки — `renderToResponse`; контент —
  общие фикстуры `fixtures.ts` через `vi.mock('astro:content')`, режим сборки —
  `vi.stubEnv('DEV', false)`. Логика страницы — в `.ts`-модели рядом с её разметкой
  (`_blog/models.ts`), её unit-тест — там же
- **Локали** — тест не знает набора локалей сайта: одна локаль или три, с ru или без — правка данных, а
  тесты те же. Тест на данных сайта (страницы, словари, снимок, `redirects.yaml`) идёт по его дескриптору и
  карте: дефолтная локаль — `DEFAULT_LOCALE`, все — `SUPPORTED_LOCALES` и `pageLocales`, текст — `t()` и
  `formatDate()`, без литерала локали и строки словаря; так же — разметка служебной страницы (`/now`) и
  браузерный набор. Механика локалей (префиксы, переводы, переключатель, меню и подвал версии, записи на двух
  языках, формат даты) — на локалях и карте теста из `@/shared/lib/testing`: `vi.mock('@/shared/i18n')`
  фабрикой `withTestLocales` (ru, en, de; строка словаря и дата — дефолтной локали сайта, у не первой локали
  теста — с её кодом в скобках), `vi.mock('@/shared/strategy')` фабрикой `withTestSite` (карта `TEST_SITE`
  через `siteOf`), формат даты — `vi.mock('./locale')` строками `TEST_LOCALES`; код локали теста там, где тип
  ждёт локаль сайта, — `testLocale()`. Так её ветки покрыты при любом наборе локалей сайта. Другие локали —
  `filter((other): boolean => …)`: вывод предиката TS при одной локали сузил бы список до `never`
- **E2E** — Playwright на **prod-сборке** (`e2e/playwright.config.ts`). Сервер — как контейнер
  (`e2e/serve.mjs`): копия `dist/` в раскладке образа (путь сборки в её `entry.mjs` — путь копии:
  CSP статики — из её `_headers.json`; пути сборки в `entry.mjs` нет — отказ старта, а не заголовки
  `dist/` репо), штамповка `docker/entrypoint.sh`, `docker/server.mjs`,
  живость — по `/healthz` (не `/`). `node_modules` у копии — репо, со всеми зависимостями: пакет,
  которого нет в образе, набор не видит — состав `dependencies` держит `seo:check`. Порты — свободные, свои у каждого
  прогона: чужой сервер не переиспользуется (`reuseExistingServer: false`), а `dist/` остаётся
  с плейсхолдером. Цели — из сборки и контента, не демо-slug'и (`e2e/site.ts`: prerendered- и
  индексируемые страницы `dist/client`, шаблоны страниц, on-demand маршруты `src/pages`, файлы для краулеров — карта и фиды, записи
  коллекций по реестру гейтов, правила `redirects.yaml`, боты реестра `crawlers.yaml`). Заявки
  уходят в локальный приёмник `e2e/form-stub.mjs` — наружу тесты не ходят. Два набора:
  - **HTTP** (`e2e/http/`, `pnpm test:http`, шаг `pnpm check` после build) — только `request`,
    браузер не нужен: профили прод (`ROBOTS_POLICY=index`, демо-`INDEXNOW_KEY`) и staging
    (`ROBOTS_POLICY=noindex`, проект `staging`)
  - **браузерный** (`e2e/browser/`, `pnpm test:e2e`, обязательный шаг `/release`) — в настоящем
    браузере: профили десктопа (`browser`) и телефона (`phone`, касание) в Chromium, ролик-петля — ещё и в
    WebKit (`webkit`; браузеры ставит `README.md § Быстрый старт`); раскладку он судит фактами, а не снапшотами, кадры шаблонов страниц кладёт в
    `test-results/frames/<профиль>/` — для взгляда глазами

## Покрытие

- Считает сам `pnpm test` (`vitest run --coverage`): объём — `src/**/*.{ts,astro}` вместе с
  `app/` и `pages/`; в выводе — файлы с дырами и сводка, факт ниже порога роняет шаг `test`
- Исключения — только связки без своей логики (баррели, входы Astro, `model/collection.ts`,
  тест-хелперы и фикстуры), каждое — строкой с причиной в `vitest.config.ts`. Код, который
  трудно покрыть, — повод для теста или для `.ts`-модели рядом с разметкой страницы, а не для
  исключения
- Пороги — храповик по statements, branches, functions и lines: факт, округлённый вниз, но не
  выше 99 % (метрика на 100 % без запаса роняет гейт от первой сгенерированной функции).
  Выросло покрытие — пороги растут тем же коммитом; опускаются только вместе с удалением
  покрытого кода или сменой инструмента — с причиной в коммите и не ниже пола 90 %. Цель — 95 %
- Обновление Vitest, Astro или Node сдвигает подсчёт: пороги пересчитываются к факту тем же
  коммитом, что и обновление
- Точечный прогон — `pnpm vitest run <путь>`: пороги считаются только по полному `pnpm test`
  (`pnpm test <путь>` краснеет на подмножестве)
- Новая страница, маршрут или модуль приходят со своим тестом (`/scaffold`), а не с
  исключением
- Предел храповика: запас под порогом — около 5 statements, поэтому маленькая страница без теста
  шаг `test` не роняет. Тест к ней требует `/scaffold page`, а саму страницу держат `seo:check` и
  HTTP-набор (on-demand маршрут — ещё строка карты в `check:content`)
- Покрытие говорит, что код исполнялся, а не что он проверен: тест пишется по смыслу — исход и
  контракт (статус, заголовок, разметка, строка лога), а не строки реализации; граница бюджета —
  литералом, а не константой модуля под тестом

описан только здесь, остальные документы ссылаются сюда:

| `check:content` | контент (схема, даты не из будущего, тело без скрытой разметки), `redirects.yaml` и карта on-demand маршрутов — до сборки |
