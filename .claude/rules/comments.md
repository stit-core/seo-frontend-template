# Комментарии

**По умолчанию — не писать комментарии.** Пиши их только когда:

- неочевиден **зачем** (скрытая инвариант, workaround под конкретный баг,
  surprise для читателя)
- решение **противоречит** интуиции — поясни выбор

**Не пиши**:

- что делает код (хорошо названные идентификаторы это уже делают)
- ссылки на текущую задачу/тикет/каллера (это в git log / PR описании)
- «был X, стал Y» (forward-only)
- многобукв-докстринги для очевидных функций

**Стиль**:

- На русском (см. global CLAUDE.md)
- Однострочные `// …` предпочтительнее многострочных блоков
- В компонентах — лучше пояснить prop через имя, чем через комментарий

## Примеры

```ts
// Bad — описывает что:
// Возвращает сумму
function add(a: number, b: number) { return a + b }

// Bad — описывает текущую задачу:
// Добавлено для тикета FE-123
function getCsrfToken() { … }

// Good — поясняет почему:
// Service Worker MSW шлёт fetch до /api/* — bypass для статики не нужен.
await worker.start({ onUnhandledRequest: 'bypass' })
```
