# Формы и антиспам

Форма работает **без JavaScript**: браузер шлёт обычный `POST` на `/api/contact`
(`application/x-www-form-urlencoded`), сервер отвечает разметкой или редиректом. Островок формы
не нужен и не заводится — всё, что он мог бы улучшить, уже делает браузер.

Форма — движок `features/lead-form` над набором каталога базы `lead-forms.yaml`, который называет
действие плана (`form.ref`): поля по порядку набора, их вид, обязательность (метки — у меньшей
группы, `minority-rule`), «хотя бы одно из», ловушка каталога; варианты канала связи — каналы, которые
бизнес ведёт (факты телефона, почты, мессенджера), почта — только у набора с полем почты. Подписи полей, вариантов и групп, ошибки и сводка —
словарь фичи на каждой локали (`label` каталога — образец русской). Скрытые поля без JS — `form_id`
(`<страница>/<секция>`) и `page_url`, их пишет сборка; набор, который форма без JS не соберёт (успех
`inline`, согласие без галочки, рекламное согласие без своего текста, шаги, поле файла), — ошибка
сборки с ключом действия. Согласие — галочка с текстом секции, рядом ссылка на политику её версии по
карте, подписанная заголовком документа на его языке (`lang`).

## Маршруты и ответы

- Страница с формой (`/contacts`, `/<lang>/contacts`) — **prerendered и индексируемая**; обработчик
  (`pages/api/contact.astro`) — `prerender = false` и **страница**, а не endpoint: без JS ответом
  на POST обязана быть разметка
- Обработчик один на все формы планов: белый список — формы страниц его реестра на каждом их языке
  (`formsOf`: строка реестра маршрута — данные страницы с формой и проекция политики согласия),
  `form_id` и `page_url` заявки называют одну из них, иначе `400`. Страница плана с формой без строки
  реестра — красный тест маршрута
- Успех — **PRG**: `303` на страницу «спасибо» формы плана (`form.thank_you_page`) своей локали, F5
  не переотправляет заявку; страница подтверждения — `noindex` и вне sitemap
- Ошибка валидации — `200` со страницей формы: её каркас, мета, h1 (`seo.h1` плана; без него страница
  с формой — ошибка сборки) и секция формы, которой пришёл ответ, — сохранённые значения, сводка
  `role="alert"` со ссылками на поля, `aria-invalid` + `aria-describedby` у полей. Другие секции
  страницы ответ не рисует: их данные (записи коллекции, картинки) серверному бандлу маршрута не
  нужны. id полей, сводки и согласия — от секции плана: две формы на странице не делят id
- Сбой доставки — `500` с тем же экраном и текстом о сбое: заявку не «принимают» молча
- Ответ с ошибками начинается с отказа — без JS: сводка подписана своим заголовком и получает
  фокус при загрузке (`tabindex="-1"` и `autofocus`: чтец экрана и клавиатура стартуют с неё, а не
  с начала страницы), `<title>` открывается словом «Ошибка: » (вкладка называет отказ раньше
  текста). Пустая форма фокус не забирает; `autofocus` у любого элемента, кроме объявления об
  отказе (`role="alert"`), — ошибка ESLint (канон UI): поле с ним забирало бы фокус на каждой
  загрузке страницы
- Отказ **до** разбора заявки — короткий текст, а не страница: `403` (чужой или отсутствующий
  `Origin`), `400` (тело не форма, не разбирается или форма не из белого списка), `413`
  (`Content-Length` больше лимита). Рисовать форму нечему: значений нет. Текст — строка словаря фичи
  (`refusal.<отказ>`) на языке префикса пути `Referer`, без него — основном: поля локали в
  непрочитанном теле нет. GET обработчика — `303` на страницу формы языка `Referer`
- Каждый отказ и каждая страница ответа обработчика — `Cache-Control: private, no-store` и
  `noindex` (в полях персональные данные, а отказы вне индекса по смыслу); 303 несёт только
  `Location`

## Антиспам-лестница (порядок обязателен)

Ступени 1–3 — функции `shared/antispam` (`isTrustedOrigin`, `isTooLarge`, `readForm`, `isTrapped`), их зовёт
обработчик формы по порядку; обоснование каждой — здесь, у кода — одна строка со ссылкой на это правило.

1. **origin-check** — антиспам-ступень, а не граница CSRF, и целиком наша: `security.checkOrigin`
   Astro **выключен** осознанно (`astro.config.ts`). За TLS-терминирующим прокси адаптер строит
   URL запроса как `http://<Host>`, `X-Forwarded-Proto` не читает — встроенная проверка отвечала
   бы `403` на любой POST формы из браузера, ещё до маршрута. Origin берётся из `Origin`, иначе
   из `Referer`, и обязан совпасть с origin runtime `SITE_URL` **или** с origin запроса (прямое
   обращение к контейнеру). Ни `Origin`, ни `Referer` — отказ: браузер шлёт `Origin` на POST
   формы всегда. Чужой сайт браузером заявку не подделает (`Host` — цели, `Origin` — его), а
   скрипт с чужим `Host` и тем же `Origin` прошёл бы: его не пускает Host-роутинг edge
   (`Host(<домен>)`, порт контейнера не опубликован). Подделывать нечего — у формы нет ни cookie,
   ни сессии, поэтому ступень отсекает спам, а не чужие действия от имени пользователя
2. **размер и форма тела** — `Content-Length` больше лимита формы (64 КБ) → `413` до чтения тела:
   разбор формы буферизует его в heap процесса. Тело без длины (`Transfer-Encoding: chunked`)
   эта ступень не меряет: оно читается до `bodySizeLimit` адаптера в `astro.config.ts` (1 МБ —
   дефолт 1 ГиБ здесь не годится; дальше — битый разбор и `400`), а 64 КБ для него держит
   буферизация прокси (`form-body-limit`). Не `application/x-www-form-urlencoded` и не
   `multipart/form-data` (или тело не разбирается) → `400` с логом уровня `warn` и **без события
   в Sentry**: иначе бот одним curl'ом жжёт квоту наблюдаемости
3. **honeypot** — скрытое поле каталога (`antispam.honeypot.field` в `lead-forms.yaml`:
   `company-website`): заполнено → ответ как у человека (303), доставки нет. По ответу ловушку не
   различить
4. **правила набора** — `features/lead-form/model/schema.ts` по набору `form.ref` плана: обязательные
   поля, вид и длина значения, вариант из списка, «хотя бы одно из» (`one_of_required`) и согласие
   `literal(true)` **и на сервере**: без галочки обработка шла бы без согласия (152-ФЗ ст. 9 ч. 1),
   а валидация обходилась бы curl'ом. Форма заявки — по скрытым `form_id` и `page_url`: форма плана
   на версии своей страницы, иначе `400`
5. **rate-limit** — на Traefik, не в приложении: счётчик в памяти процесса не переживает рестарт
   и не виден второй реплике. Это требование деплоя, а не опция: контракт
   `docs/reference/infra-handoff.md § Edge`, без лимита форму наружу не открывают

Time-trap (подписанная метка времени) в шаблоне **нет**: метку выдаёт рендер страницы, а страница
с формой prerendered — на сборке честной метки не существует. Появится он вместе с формой,
которую рендерит запрос, либо вторым островом; в обоих случаях — решением проекта. Капчи в шаблоне
тоже **нет**: ступень, которая ничего не проверяет, — ложная защита; провайдер появляется решением
проекта по логам атаки (норма базы strategy — `antispam.captcha` каталога `lead-forms.yaml`) вместе
со своей ступенью, ключами env и тестом.

## Доставка

- Один канал: `FORM_DELIVERY=smtp|backend`, три попытки с паузами; `nodemailer` грузится
  динамическим импортом только на канале `smtp`
- Незаданный адрес канала — ошибка **при отправке** (честный 500), не при старте: сайт без
  настроенной формы обязан подниматься и отдавать контент
- Durable-спул на диске и второй канал — решение проекта (нужен volume и ретенция ПДн), не код
  шаблона. Заявка уходит синхронно, ответ — после попытки доставки
- Вместе с заявкой уезжает запись согласия (`defaults.consent.record` каталога): `consent_version` —
  дата редакции политики (факт, который план политики связывает с её датой, — та же дата на её
  странице), `consent_at`, `page_url`, `form_id`, `marketing_consent`; рядом — метки рекламы
  (`utm_*`, `yclid`, `gclid`), которые без JS ставит сервер из query `Referer`

## Персональные данные

- **Тело заявки не логируется** никогда: в лог — `evt: contact`, результат, канал, число попыток
  и `rid` (тот же, что в `X-Request-Id`). Пишет один логгер на всё приложение — `log()` из
  `shared/observability`, с порогом `LOG_LEVEL`. Sentry получает исключение доставки, не заявку
  и не отказы ступеней
- Политика ПДн — обязательная страница карты: ссылка в подвале и рядом с формой; текст — copy deck
  страницы `privacy`, реквизиты оператора — факты проекта (`legal.operator_ref` плана,
  `strategy/facts*.yaml`); у шаблона это демо-факты (`example: true`), и `/de-template` обязан
  падать, пока хоть один остался
- Одна цель — одна галочка; предустановленной она не бывает. Вторая цель (рассылка) — второе поле
- Хранение заявок — на стороне канала доставки и в РФ; зарубежные форм-сервисы запрещены
