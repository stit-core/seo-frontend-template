# Контент-инварианты

Контент — Markdown в git внутри слайса сущности (`src/entities/<name>/content/`), схема —
Zod в `model/schema.ts` (прямой `import { z } from 'zod'`), коллекция — `model/collection.ts`
(`glob({ base })`), доступ — `api/queries.ts`. Ошибка схемы = красная сборка; раньше и
понятнее её ловит `pnpm check:content`.

## Файл записи

- Путь: `content/<locale>/<slug>.md`. **Язык задаёт каталог** — поля `lang` нет; `<locale>`
  ∈ `SUPPORTED_LOCALES` (`shared/i18n`); slug — только `a-z`, `0-9`, дефисы. Id записи —
  `<locale>/<slug>`, URL — `/blog/<slug>` (`/en/blog/<slug>`)
- Frontmatter — строгая мапа (неизвестное поле, в т.ч. опечатка, — ошибка):
  `title` (25–65 символов), `description` (70–170), `pubDate`, `updatedDate?` (не раньше
  `pubDate`; источник `dateModified` в JSON-LD и `lastmod` в sitemap — у записи без правки
  `lastmod` — её `pubDate`), `cover?` +
  `coverAlt?` (только вместе; из обложки сборка делает и превью ссылки `og:image`, и кадры разметки
  статьи), `tags` (slug'и, без дублей),
  `draft` (по умолчанию `false`), `translationKey` (slug, общий для переводов), `author?` (id
  реестра `src/entities/author/model/authors.ts`; id вне реестра — ошибка схемы)
- Автор — запись реестра `AUTHORS`: имя и роль по локалям; у записи с `author` страница печатает
  подпись под заголовком и `Person` в разметке — одними и теми же строками. Реестр шаблона пуст:
  автор — реальный человек, который написал или проверил текст. Схема реестр не импортирует
  (соседний слайс): id авторов ей передаёт тот, кто собирает коллекцию, — `src/content.config.ts`
  и реестр гейтов `scripts/lib/content.mjs`
- Бюджеты `title`/`description` — часть схемы: это ширина сниппета выдачи, не «пожелание».
  `title` и `description` уникальны внутри локали — у каждой страницы свой сниппет
- YAML — полный (`js-yaml`, им же Astro читает frontmatter): значение с `: ` или с ведущим
  спецсимволом — в кавычках. Дата без времени (`2026-01-01`) — календарная, полночь UTC;
  `formatDate`/`isoDate` (`shared/i18n`) тоже считают в UTC, поэтому день не «съезжает»
  ни в каком часовом поясе сборки
- Даты опубликованной записи (`pubDate`, `updatedDate`) — не позже дня проверки (`check:content`):
  дата из будущего уехала бы в разметку, карту сайта и фид — поисковик читает её как подделку
  свежести. День проверки — самый поздний календарный день, который уже наступил где-то на Земле
  (пояс UTC+14): ответ не зависит от пояса машины, и сегодняшняя дата автора из любого пояса — не
  будущее; цена — «завтра» по часам машины проходит, когда этот день на Земле начался (в Москве — с
  13:00). Запланированная запись ждёт своего дня с `draft: true` — черновику дата из будущего
  позволена
- Литерала плейсхолдера origin (хост из `SITE_ORIGIN_PLACEHOLDER`, `shared/config`) в записи
  нет ни во frontmatter, ни в теле: штамповка при старте контейнера переписала бы его в
  HTML. Описывать словами («фиктивный origin-плейсхолдер»), не литералом

## Тело

- Ровно один `<h1>` на странице — из `title`; в теле заголовки только `##` и глубже, без
  скачков уровней; заголовок подчёркиванием `===` и сырой `<h1>` тоже запрещены
- У каждой картинки — осмысленный `alt`; путь — относительный от файла, файл существует
- Ссылки на свои страницы — корневые (`/blog/x`), без хвостового слеша и `.html`, только
  на существующие маршруты (черновик — не маршрут); относительные `./x.md` запрещены. Ссылка на
  файл `public/` с кириллицей в имени законна в обеих записях — буквами и процентами
- В теле нет `<script>` и `meta refresh`; абсолютные URL своего origin — только в `<head>`
- Сырой HTML в теле — без атрибутов `style`, `class`, `hidden` и `aria-hidden` (`check:content`).
  Текст, которого читатель не видит, — текст только для роботов: для поисковика это спам, для
  ИИ-ответов — причина не цитировать страницу. `style` к тому же блокирует CSP страницы — в гейте
  это увидел бы только браузерный набор; вид записи задают стили статьи, а не классы в тексте.
  Правило — страховка от удобного пути, а не от обфускации: скрытие без этих атрибутов
  (`<template>`, `<dialog>`, `<noscript>`, цвет текста, атрибуты SVG) оно не видит
- Колонки таблицы Markdown — без выравнивания (`:--`, `:-:`, `--:`): сборка печатает его атрибутом
  `style` каждой ячейки, а инлайн-стиль блокирует CSP страницы (`check:content`)
- Тело гейт читает разборщиком сборки (satteri — им Astro собирает записи; теги сырого HTML — его
  же HTML-разборщиком, как браузер), и правило смотрит на узел дерева, а не на запись. Код — в
  бэктиках любой длины, оградой или отступом — текст, а не разметка; ссылка и картинка по метке
  (`[текст][метка]`) проверяются как обычные; то, что Markdown тегом не признал (`<p/hidden>` в
  абзаце), читатель видит текстом — нарушения нет
- Слова — на авторе: ответ первым, подзаголовок-вывод, факт с датой и источником, никаких
  инструкций моделям — раздел «Текст для поиска и ИИ-ответов» скилла `/content`; словари держит
  линтер базы strategy (`copy_lint.py`), в шаблон они не копируются

## Черновики и переводы

- `draft: true` виден только в `astro dev` (`import.meta.env.DEV` в `api/queries.ts`): в
  списках, тегах и по URL, с пометкой «Черновик» в карточке и статье. В сборке записи нет
  нигде — не в списках, не в тегах, URL — 404 (и не будет в sitemap/RSS); страницу черновика в
  `dist/client` валит `seo:check`. Preview-режима
  нет; ссылка на черновик из опубликованной записи — ошибка `check:content`
- Переводы — параллельные каталоги `ru/`, `en/` с общим `translationKey`; slug'и могут
  отличаться. `translationKey` уникален внутри локали; запись без twin — норма.
  Fallback-режима нет: непереведённая запись под другой локалью — 404, а не копия. Ссылка
  на перевод (и hreflang) — только при реальном twin (`findTranslation`)
- Обложка — мастер 1600×900 в `content/covers/<translationKey>.<jpg|png>`, общий для локалей:
  `cover: ../covers/<key>.jpg` + `coverAlt` (что на картинке — предложением, с её надписями). Фото —
  JPEG, плоская графика (схема, надпись, иллюстрация в несколько цветов) — PNG: PNG фото весит в разы
  больше. Из мастера сборка делает AVIF и WebP страницы, превью ссылки 1200×630 и кадры разметки
  статьи 16:9, 4:3 и 1:1 в JPEG (`shared/seo`); кадры не растягиваются — у мастера мельче превью
  ссылки файл выходит не по норме, и `seo:check` краснеет

## Списки

- `/blog` — страница 1; `/blog/page/N` — только 2…N (`/blog/page/1` нет; ровно 5 записей —
  одна страница, пустых нет); у страницы N — `title`, `description` и `h1` с суффиксом
  «— страница N»; страницы тегов — только для тегов видимых записей. Страница тега индексируется
  от трёх опубликованных записей локали (`isTagIndexable`, `entities/post/lib/tags.ts`): ниже
  порога она почти повторяет список — собирается, но с `noindex`, вне карты сайта и hreflang;
  ссылка на перевод тега — только на страницу другой локали от порога. `getStaticPaths`
  ru/en-обёрток — общие функции `src/pages/_blog/static-paths.ts`

## Редиректы — данные

- `content/redirects.yaml`: список `{ from, to?, status, note? }`; `status` ∈ `301 | 308 |
  410`; у `410` нет `to`; `to` — свой корневой путь в канонической форме (нижний регистр, без
  query и хвостового слеша) **или** абсолютный `http(s)` URL. Чужой адрес пишется как есть
  (`https://пример.рф/раздел`) и приводится к одной записи — хост в punycode, путь и query в
  процентах: не-ASCII заголовок `Location` не принимает. Пустой файл (или только
  комментарии) — пустая таблица
- `from` — адрес старого сайта как он был: заглавные, кириллица (буквами или процентами),
  хвостовой слеш, `index.php`, `?query`. К таблице он приводится тем же каноном пути, что и адрес
  запроса (`canonicalPath`, `shared/redirects`): `/Услуги/`, `/%D0%A3…` и `/%d0%a3…/` — одно
  правило. Регистр — часть адреса: `/Old-Page` не срабатывает на `/old-page`. Правило с `?query`
  срабатывает, когда в запросе есть все его пары (из подходящих — самое точное); эти пары в
  `Location` не переезжают, остальные параметры запроса — переезжают. Спрятанный разделитель
  (`%2F`, `%5C`), пробел и `#` в `from` — ошибка схемы
- Один хоп у каждого адреса таблицы: `to` не совпадает ни с чьим `from` без query (нет цепочек и
  циклов), внутренний `to` существует, дублей `from` нет — и две записи одного адреса (`/a/` и
  `/a/index.html`) тоже дубль (`shared/redirects` + `check:content`). Правило с `?query` на пути
  чужой цели законно: два хопа получит только запрос, который сам принёс его пары на адрес другого
  правила, — адрес, которого у старого сайта не было. `from` на пути существующего маршрута — только переезд с
  `?query` (`/?p=123` старого сайта): без query он закрыл бы страницу, а 410 там перекрыла бы
  сама страница
- YAML разбирается на сборке (плагин `yaml-modules` в `astro.config.ts`, `js-yaml`;
  тип `*.yaml` — `src/env.d.ts`): в серверный бандл попадают данные, а не парсер; Zod
  проверяет их при загрузке модуля, файл в контейнере не нужен
- Обслуживает одна таблица (`app/middleware/redirects.ts` → `resolveRequest`) в двух местах.
  Переезд (301/308) и неканоническую форму любого адреса отдаёт обёртка процесса
  `docker/server.mjs` — раньше статик-хендлера, поэтому `/old/`, `//old` и `/old/index.html` ведут
  сразу на цель, а правило на пути живой страницы срабатывает; модуль таблицы сборка кладёт ей
  отдельным файлом `dist/server/redirects.mjs`. Удалённый адрес (410) отвечает `app/middleware`
  до роутинга — `404.astro` поэтому on-demand: иначе путь без файла не дошёл бы до middleware.
  410 отвечает одна форма удалённого адреса — каноническая: с любой другой, и с записи `from` со
  слешем старого сайта, — один 301 на неё.
  В `astro dev` обёртки нет: на адрес без страницы (переезд, 410) отвечает middleware, а правило
  с `?query` на пути prerendered-страницы и неканоническая форма её адреса там не срабатывают — их
  держит HTTP-набор на сборке. Адрес читают только GET и HEAD.
  `410` — тело без стилей на языке префикса удалённого адреса + `X-Robots-Tag: noindex`
- `meta refresh` и `redirects` в `astro.config.ts` не используются. Ссылок на адреса из
  `redirects.yaml`, ссылок в неканонической форме (двойной слеш в пути, буква процентами) и ссылок
  без схемы на другой хост (`//contacts` — так склеивается путь с лишним слешем) в разметке нет —
  `check:links` читает ссылку как браузер; кириллицу в пути и сегменты `.` и `..` браузер приводит сам до
  запроса — такая ссылка законна, а существование её цели сверяется в записи файла: имя — буквами

## Гейты

- `pnpm check:content` (до `build`): схема каждого `.md`, даты не позже дня проверки, тело (и
  скрытая разметка в нём), литерал плейсхолдера,
  уникальность `title`/`description`/`translationKey` в коллекции и локали, ссылки по списку маршрутов
  (`src/pages` + контент + `public/` + карта сайта — файл сборки), `redirects.yaml`
- `pnpm check:links` (после `build`): каждый внутренний `href`/`src`/`srcset` в
  `dist/client` существует (файл — под именем буквами, `<path>/index.html` или on-demand маршрут),
  и путь, каким его запросит браузер, — каноническая форма адреса; свой адрес пишется с одним
  слешем, чужой — со схемой
- Скрипты читают YAML напрямую `js-yaml` и исполняют TS-модули напрямую (Node strip-types),
  поэтому импортируют только «листовые» модули без `@/`-алиасов и относительных импортов:
  `model/schema.ts`, `lib/paginate.ts`, `entities/author/model/authors.ts`,
  `shared/redirects/table.ts`, `shared/i18n/locale.ts`, `shared/config/runtime.ts`,
  `shared/config/site.ts` (его читает политика сборки), `shared/config/islands.ts` (реестр
  островов, импорт — `./site.ts` с расширением), `app/styles/fonts.ts` (список шрифтов ДС), `shared/seo/sitemap.ts` (формат карты —
  генератору `scripts/lib/sitemap.mjs`); импорт в `authors.ts` и `site.ts` — только типов
- Новая коллекция — запись в реестре `collections` модуля `scripts/lib/content.mjs` (каталог,
  схема, порождаемые маршруты): каталог `src/entities/*/content` вне реестра и запись реестра без
  каталога — ошибка `check:content`. Скрипты берут реестр проверяемого корня: у мини-проектов
  `.gate-fixtures/` он свой, и коллекции сайта гейта на гейт не касаются
- Сами скрипты под гейтом: негативные фикстуры `.gate-fixtures/{content,links}` обязаны давать
  ровно нарушения из `expected.json` (`pnpm check:gate`); новая проверка — новое нарушение в
  фикстуре тем же коммитом
