# Forward-only

Все артефакты — код, документация, комментарии, описания PR и коммитов —
пишутся в режиме «что есть и куда идём». **Без журналов прошлого**:

- ❌ changelog'и внутри prose
- ❌ ссылки на отменённые решения («раньше было X, сейчас Y»)
- ❌ даты в комментариях («с 2025 года…»)
- ❌ «было / стало», «теперь / больше не», «до развязки»
- ❌ имена переходных фаз

Когда эволюция вынесла факт — упоминание **удаляется**, не сопровождается
пометкой «устарело». История живёт в `git log`, не в тексте файлов.

Правило важнее, чем «не сломать кросс-ссылку»: ссылка на упразднённую
сущность удаляется вместе с упоминанием.

## Планы — forward-only, без архива

Единый `.claude/plans/roadmap.md` описывает только то, что **ещё предстоит**.
Активные планы — `### `-секции под `## Active`; по завершении секция
**удаляется целиком** — история остаётся в `git log`. Секции «Выполненные»
нет, закрытый план не «переезжает» в `## Backlog` как референс (это и есть
архив в артефакте). Незакрытые follow-up'ы из закрытой задачи переезжают
строкой в `## Backlog`, а не остаются хвостом в удаляемой секции.

## Исключения

- `git log`, commit-сообщения (там история уместна по дизайну)
- `CHANGELOG.md` если он явно автогенерирован (для шаблона приложения — не нужен)
