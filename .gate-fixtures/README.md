# Негативные фикстуры гейта

Мини-проекты с заведомыми нарушениями. `pnpm check:gate` (`scripts/check-gate.mjs`) гоняет на
них **корневые** конфиги линтеров и **собственные скрипты гейта** (и скрипт релиза `indexnow` —
сценариями) и падает, если найденное хоть в чём-то расходится с `expected.json`: ожидаемое нарушение не поймано (правило выключено,
понижено до warn, проверка в скрипте ослаблена) или поймано лишнее (ожидание удалено —
`expected.json` урезан). Пустая секция — тоже ошибка: гейт на гейт выключен. Это защита от
молчаливых деградаций: Steiger fail-open на нерезолвимых импортах, выключенная a11y-группа Biome
пропускает разметку без `alt`, `boundaries` без резолвера не видит `@/`-импорты, правка
`seo:check` «под новую коллекцию» тихо выключает сверку.

## Скрипты гейта — `seo/`, `links/`, `content/`, `plans/`

Каждый каталог — корень мини-проекта (`dist/client`, рантайм `dist/server` и `docker/` с
`package.json`, `src/pages`, контент коллекций,
`content/redirects.yaml`, свой реестр коллекций `scripts/lib/content.mjs`, островов и локалей
`scripts/lib/site-policy.mjs`; у `seo/` — ещё свой снимок strategy `strategy/`), скрипт запускается
с ним аргументом: `node scripts/seo-check.mjs .gate-fixtures/seo`. Реестр скрипт берёт из
проверяемого корня, поэтому коллекции сайта — новая по `/scaffold collection`, переименованная
или удалённая прунингом — и его острова и локали фикстур не касаются. В `expected.json` — строки нарушений ровно так,
как скрипт их печатает; где дальше идёт текст сторонней библиотеки (Zod, js-yaml), строка
ожидания обрывается на `…` и сверяется по началу — обновление зависимости гейт не роняет, а свои
сообщения скриптов на `…` не заканчиваются. Валидатор планов берёт корень из git, поэтому
запускается в `plans/` как в корне проекта (`GIT_CEILING_DIRECTORIES` не пускает git выше), а
его строки в `expected.json` — `E …` отчёта.

Часы у фикстур свои: скрипты гонятся с `--import clock.mjs` — в одном замороженном моменте — и в
поясе позади UTC (`TZ=America/New_York`). «День проверки» дат записей поэтому не сдвигается с днём
прогона, а его независимость от пояса машины — под гейтом: момент — полночь самого раннего пояса
Земли, где новый день уже начался, а по UTC и по часам прогона — ещё нет.

## Скрипт релиза — `indexnow/`

`pnpm indexnow` (`scripts/indexnow.mjs`) ходит по сети, поэтому сайт (карта и файл ключа) и
приёмник адресов для него — один локальный сервер внутри `check:gate`: наружу гейт не ходит.
`before.xml` — карта до выката, `after.xml` — после: главная и запись `prezhnyaya` не менялись,
у `pravlenaya` сменился `lastmod`, `novaya` появилась, `udalyonnaya` пропала; в файлах — плейсхолдер
origin, заглушка ставит свой адрес. В `expected.json` — исходы сценариев: код выхода, адреса,
которые скрипт назвал (`+` новый, `~` изменённый, `-` удалённый), и то, что дошло до приёмника
(`→`).

| сценарий | что обязано быть |
|---|---|
| отправка | приёмнику — один запрос в JSON (запрос без `Content-Type: application/json` заглушка отклоняет, как приёмник протокола) с `host`, `key` и `keyLocation` сайта и ровно три адреса: новый, изменённый, удалённый |
| сухой прогон (без `--send`) | те же три адреса названы, запросов приёмнику нет |
| без ключа; чужой ключ (живой файл отвечает другим) | отказ с кодом 1, запросов нет |
| карта не изменилась | код 0, запросов нет |
| первый выкат (карты «до» нет) | все адреса карты — новые |
| карта «до» с другого сайта | отказ с кодом 1, запросов нет |
| карта «до» без адресов (`ne-karta.html` — страница ошибки вместо карты) | отказ с кодом 1, запросов нет: иначе изменёнными стали бы все адреса сайта |
| приёмник отказал (заглушка отвечает 403) | три адреса названы и дошли до приёмника, его отказ — отказ скрипта: код 1 |

## Периметр — `guard.json`

Сценарии guard-хука Claude Code (`.claude/hooks/guard-bash.sh`): `block` — обходы git-хуков и
force-push (`git commit -n`, `--no-veri…`, `core.hooksPath`, `LEFTHOOK=0`, `LEFTHOOK_EXCLUDE`,
`lefthook uninstall`, запись в `.git/hooks` и `lefthook-local`, в том числе `sed -i` и `perl -i`) —
и они же в теле `bash -c`, `eval` и heredoc оболочке, каждому — отказ с кодом 2; `allow` — обычная
работа (коммит с heredoc-сообщением, `--amend`, `git worktree add/remove`, `git restore`, push без
force, `lefthook install`, чтение хука, `sed -i` по коду, heredoc оболочке с обычной командой),
каждой — пропуск. Пустой `block` — красный.

## Как менять

Новое правило границ в корневом конфиге или новая проверка в скрипте гейта — новое нарушение в
фикстуре + строка в `expected.json` тем же коммитом. Изменился текст сообщения скрипта или
линтер стал находить больше — `expected.json` правится вслед, осознанно: расхождение и есть
сигнал. Каталог исключён из обычных прогонов (`tsconfig`, `biome.json`, `eslint.config.js`,
`.dockerignore`); мини-сборки `*/dist` — в git (`.gitignore` их не прячет).
